SC-31 — 거래처 기준정보 설정

Common 목표 경계: 2026-08-20 설정 진입·App User. 목표 표면은 Common 설정 허브의 Trade OS 구획이며, 이 문서는 제품 필드·저장·업무 오류와 기존 /erp/settings 구현을 소유한다.

결정 근거: TRADE-DOC-001 — QA 절의 규범 경계 · DEC-TRD-009 — 지원 locale과 fallback · DEC-TRD-010 — 접근성 기준과 검증 범위

확정 근거: ISSUE-144 — 영향 preview와 사용자 확인 기반 거래처 병합 · 구현·QA 충족 여부는 이 문서와 별도로 검증한다.

접근 현재 Space Owner/Admin만 병합 preview·execute; Member·unknown 거부, cross-Space 대상 비열거

이 화면은 공통 UI 품질 계약의 locale·접근성 기준을 상속한다. 병합 미리보기·충돌 선택·확인 대화상자는 locale resource를 사용하고 키보드와 스크린 리더로 검토·취소·실행과 오류 복구를 완료할 수 있어야 한다.

QA 기준

이 절은 앞선 제품 계약을 검증하기 위한 점검 항목이며, 독립적인 제품 요구사항을 추가하지 않는다.

원본·대상 거래처 ID, 기준명, 역할, 별칭, 병합 확인값, preview revision/digest, idempotency key, 처리 영수증을 기록한다. 병합은 단순 이름 변경이 아니다.

  • Owner/Admin만 preview와 execute를 호출한다. Member와 알 수 없는 역할은 둘 다 거부한다.
  • preview에는 Deal party, 받은/생성 문서, SNAP 연결, alias/learning, 일정, 보관·취소·마감·과거 이력과 통화별 원금·미수/미지급·원본 현금·분쟁·환불/반환·조정을 포함한다.
  • 원장 coverage가 완전하고 값이 실제 0일 때만 0을 표시한다. unavailable은 — 또는 0으로 바꾸지 않고 “계산 불가”와 reason을 표시하며 실행을 막는다. 금액은 통화별 원장 문자열을 locale 표시만 하고 합산·FX·재반올림하지 않는다.
  • 같은 값 또는 한쪽만 빈 필드는 자동 결합할 수 있다. 국가·통화·등록번호·은행·역할 충돌은 사용자가 최종값을 선택하기 전에는 진행하지 않는다.
  • source·target 또는 종속 writer가 preview 뒤 바뀌거나 10분이 지나면 stale로 거부하고, 입력한 사유·충돌 선택을 보존한 채 최신 preview와 달라진 항목을 다시 보여준다. 기존 bodyless 실행은 MERGE_PREVIEW_REQUIRED로 거부한다.
  • 실행은 target 재연결, source 비활성, lineage 기록, 영수증 생성을 모두 성공시키거나 모두 실패시킨다. 같은 idempotency key와 같은 payload의 재시도는 같은 영수증을 반환한다.
  • source·target 확인 문구, reason_code와 1~500자 note, 충돌별 선택, “원본·대상과 영향을 확인했습니다” checkbox가 모두 있어야 실행 버튼이 활성화된다. 제3의 필드값이 필요하면 대화상자를 닫고 기준정보를 수정한 뒤 새 preview를 만든다.
  • 대화상자는 키보드만으로 탐색·취소·실행할 수 있고 focus trap/복귀, 제목·설명 연결, 오류 첫 항목 focus, 색상 외 상태문구를 제공한다. 모든 문구는 locale resource를 사용한다.
  • source가 이미 병합됐으면 최종 canonical target과 기존 receipt로 이동한다. future writer가 source를 다시 활성화·참조하는 경로와 병합 chain cycle을 허용하지 않는다.
  • 병합을 취소해 과거를 다시 쓰지 않는다. 잘못된 병합은 새 기준정보와 명시적 재연결 사건으로 forward correction한다.

상태·오류·복구

상태 화면 표시 허용 행동 복구
preview 조회 중 source·target 고정, skeleton 취소 같은 후보로 재시도
preview 준비 종속·금액·충돌·사유·확인 충돌 선택·병합 unavailable/hard conflict는 관련 원본 수정 후 새 preview
preview stale/expired 달라진 writer·항목, 기존 입력 보존 최신 영향 다시 확인 새 digest를 받은 뒤 재확인
execute 중 중복 클릭 차단, 처리 중 취소 불가 동일 idempotency key로 결과 조회
execute 성공 canonical target·이동 링크·receipt ID 대상 열기 잘못된 결과는 forward correction 시작
권한/대상 오류 MERGE_FORBIDDEN, COUNTERPARTY_NOT_FOUND 설정 복귀 다른 Space 존재 여부를 노출하지 않음

backend v2 capability가 없거나 execute gate가 닫혀 있으면 병합 CTA를 숨기고 “현재 병합을 사용할 수 없습니다”를 표시한다. 구형 bodyless 호출로 fallback하지 않는다.
