4. 업무 규칙과 표시 기준

  • Owner/Admin은 조직 범위 카드와 회사 전체 보기를 조회한다.
  • Member는 본인 담당·공동 작업 카드를 우선 조회하고 회사 전체 요약도 볼 수 있다.
  • 카드 조회 범위와 원천 업무 실행 권한을 분리한다. 카드를 볼 수 있어도 권한 없는 행동을 실행할 수 없다.
  • 실행 불가 행동은 업무 자체를 숨기지 않고 권한이 없어 조회만 가능과 담당자·권한 요청 경로를 표시한다.
  • 운영 감시 메뉴는 Owner 전용이라는 기존 결정을 유지한다.

근거: OPEN-015.

공통 UI 품질 계약 적용

공통 UI 품질 계약이 정한 모바일 compact 범위에서 내 할 일과 팀 현황의 목록, 실제 빈 화면, 조회 오류와 재시도 행동을 안전하게 표시한다. 목록·표가 화면보다 넓으면 해당 컨테이너 안에서만 가로 스크롤하고 페이지 전체의 수평 overflow를 만들지 않는다. 관련 업무 화면으로 이동하는 링크와 복구 행동은 compact 표시에서도 유실되지 않아야 한다.

근거: DEC-TRD-008.

업무 데이터 기준

할 일 목록은 승인 대기, 거래 방향 확인 필요, 지급기한 초과, 예외 등 실제 업무의 현재 상태를 가져와 보여준다. 목록에서만 별도의 완료 상태를 만들지 않는다.

운영 감시 기준시각과 부분 실패

  • KPI·상태·처리량은 하나의 원자 snapshot이 아니며 각 응답의 data_as_of를 조직 시간대로 표시한다. 세 값을 min/max로 합쳐 화면 전체 기준시각을 만들지 않는다.
  • 각 영역 DTO는 area, data, UTC RFC3339 data_as_of, IANA timezone, request_id를 반환한다. 서버가 계산 시각과 조직 시간대를 정하며 프론트 수신 시각·브라우저 시간대를 정본으로 쓰지 않는다.
  • 성공한 영역은 즉시 교체한다. 실패한 영역은 마지막 성공 데이터와 기준시각을 유지하고 오류·오래됨을 함께 표시하며 다시 시도는 실패 영역만 호출한다.
  • data_as_of가 누락·null·형식 오류이거나 클라이언트 수신 시각보다 5분 넘게 미래이면 새 성공으로 채택하지 않는다. 15분보다 오래된 값은 숨기지 않고 오래됨 경고를 붙인다.
  • 같은 영역에서 늦게 도착한 이전 request 또는 더 오래된 data_as_of는 현재값을 덮지 않는다. locale 형식·초 정밀도와 조직 timezone label을 함께 표시한다.
  • risks·pending actions·blocked 등 보조 응답은 자체 기준시각이 있으면 그 영역에만 표시하고 KPI·상태·처리량 시각에 합치지 않는다.
  • 혼합 배포에서 data_as_of나 timezone이 없는 구 응답은 현재 시각으로 합성하지 않고 그 영역의 invalid timestamp 실패로 처리한다. backend additive DTO를 먼저 배포하고 영역별 UI flag를 연다.
  • rollback은 timestamp UI와 새 요청만 끄고 영역별 마지막 성공 cache를 read-only로 보존한다. 서로 다른 영역·시각의 값을 한 snapshot으로 합치거나 마지막 정상 데이터를 0·빈 상태로 덮지 않는다.

할 일 항목 최소 계약:

  • 다시 조회해도 같은 항목을 찾을 수 있는 업무 ID와 종류
  • 제목/요약
  • 담당자 또는 미할당
  • 기한/기한 초과와 시간대
  • 우선순위·중요도를 정한 기준
  • 권한 범위의 관련 업무 화면 링크
  • 실제 업무 상태와 가능한 행동

범위 규칙

  • 구성원 내 할 일: 본인 담당/처리 가능 업무
  • 소유자·관리자 내 할 일: 본인 업무
  • 운영 감시 현재 구현: 소유자만 조직 전체, 미할당, 기한 초과, 병목 조회
  • 관리자·구성원의 운영 감시 범위: 승인 전까지 허용으로 간주하지 않으며 OD-006에서 결정
  • 조직/접근 범위 밖 항목은 건수에도 포함하지 않는다.

꼭 지켜야 할 점

  • 할 일 확인/읽음은 실제 업무 완료가 아니다.
  • 같은 업무를 여러 목록에 표시해도 건수와 상태가 모순되지 않는다.
  • 관련 업무 조회 불가와 빈 목록을 구분한다.
  • 삭제/보관된 대상 링크는 복구 동선을 제공한다.
  • 모니터 시간 표시는 ko-KR, en-US, en-GB, ja-JP, de-DE, fr-FR fixture에서 locale 순서·초·명시적 IANA timezone label을 유지한다.

다음 방식은 개인 업무와 팀 현황의 대체 구조로 사용하지 않는다.

  • 상단 알림 하나에 모든 실행 업무와 팀 병목을 합치는 방식
  • 별도 권한 결정 없이 모든 구성원에게 조직 전체 현황을 공개하는 방식
  • 홈 요약과 개인 업무 목록을 같은 화면·같은 숫자로 간주하는 방식

5. 현행 QA 점검 항목

이 절은 앞선 제품 계약을 검증하기 위한 점검 항목이며, 독립적인 제품 요구사항을 추가하지 않는다.

실제 통과 기준은 6~7장의 현행 구현 상태와 프론트·API·백엔드 원본 근거가 확인된 범위로 제한한다.

  • member는 자기 범위 밖 항목/건수를 보지 않는다.
  • 소유자의 운영 감시 건수가 실제 업무 데이터와 같다.
  • 관리자·구성원이 메뉴와 직접 경로에서 운영 감시에 접근할 수 없다.
  • 미할당/기한 초과/시간대/페이지 결과가 결정적이다.
  • 본인 배정 알림의 확인 처리·해결 처리만 화면에 노출되고, 성공 뒤 열린 목록을 다시 조회한다.
  • 읽음/확인만으로 항목이 완료되지 않는다.
  • 모바일에서 실제 빈 목록·조회 불가·오류·재시도와 관련 화면 링크를 구분하고, 넓은 목록·표는 컨테이너 내부에서만 가로 스크롤한다.
  • KPI·상태·처리량의 서로 다른 기준시각과 조직 timezone label이 각각 표시된다.
  • 한 영역 실패 뒤 다른 성공 영역은 갱신되고 실패 영역은 마지막 성공값·시각과 오류를 유지한다.
  • 누락·invalid·5분 초과 미래·15분 초과 오래된 시각과 역순 응답을 정해진 규칙으로 처리한다.

6. 정책 및 구현 상태

구현 상태

ERP v2에는 통합 할 일 목록이 있고 플랫폼에는 행동 항목의 개인/조직 범위 기반이 있다. 현재 사용자 화면은 본인 배정 항목의 확인·해결과 운영 플래그 확인을 제공하지만 할당·재할당, 관리자 전용 승인·반려 버튼은 제공하지 않는다. /erp/monitor는 프론트 메뉴·보호 화면과 서버가 모두 소유자 전용이다. OD-006과 OPEN-015에 따라 Member는 본인 담당·공동 작업과 회사 요약을 보고, 실행은 원천 권한을 따른다. 현재 화면·API의 일관된 적용은 IMPLEMENTATION_GAP이다.

API·감사

  • 안정적인 페이지/정렬, 원천 필터, 개인/팀 범위.
  • 확인·해결·플래그 확인 감사는 각 원천 업무 흐름이 소유한다. 할당·재할당 화면은 현재 구현에서 확인되지 않았다.
  • 조회 모델 실패가 원천 변경을 만들지 않는다.

목록 응답은 안정적인 항목/원천 ID, 종류/상태, 제목, 담당 범위, 우선순위/기한, 원천 화면 링크를 포함한다. 필터와 페이지는 권한 범위 안에서 처리하며 상태 전이는 서버 권한을 통과해야 한다. 원천 투영 실패는 조회 불가/오류이지 빈 목록 성공이 아니다.

첫 목록 조회, 실시간/주기 갱신, 상태 변경은 각각 별도 처리 상태다. 개인 할 일 없음, 팀 병목 없음, 권한 제한, 오래되거나 삭제된 원천, 일부 원천 실패, 전체 실패를 구분한다. 업무 완료는 원천 변경이 소유하며 조회 모델이 임의 완료를 만들지 않는다.

현재 판정: 통합 원천 투영은 MATCH다. 운영 감시의 소유자 전용 강제도 프론트·서버가 일치한다. 관리자·구성원의 팀 범위와 개인/팀 구조는 OD-006·OPEN-015로 확정됐고, 남은 것은 IMPLEMENTATION_GAP이다(TR-012/016).
