SC-30 — 초대 설정

CURRENT_LEGACY: 이 문서는 기존 /erp/settings의 Space 초대 화면을 보존한다. 목표 Organization Member 초대는 Common CS-08, Trade OS App User 초대는 SC-45가 소유한다. 두 초대를 같은 역할·상태·API로 처리하지 않는다. 경계 반영: 2026-08-20.

역사 근거: DEC-TRD-006 초대 가능 역할 행렬 · DEC-TRD-011 기존 멤버 관리·자기 이탈 · 문서 규범: TRADE-DOC-001 QA 절의 규범 경계

  • 초대 폼의 역할 선택과 기존 멤버의 역할 편집은 서로 다른 행동과 권한 검사다.
  • Admin의 새 초대에는 Admin 역할이 없지만, 이 초대 행렬을 기존 멤버의 역할 변경에 재사용하지 않는다.
  • 기존 멤버 관리는 SC-29 멤버 설정과 DEC-TRD-011을 따른다. Owner와 Admin은 비-Owner·비자기 멤버를 Admin·Member로 변경하거나 조직에서 제거하고 Member는 타인 관리를 실행할 수 없다. 자기 행의 변경·제거와 워크스페이스 나가기는 초대 화면과 SC-29 모두에 없으며 자기 이탈은 Common CS-06 일반의 Trade 변형으로 분리한다.
  • 현재 Owner는 일반 역할 변경 대상이 아니며 Owner 변경은 별도 소유권 이전 절차로만 처리한다.

QA 기준

이 절은 앞선 제품 계약을 검증하기 위한 점검 항목이며, 독립적인 제품 요구사항을 추가하지 않는다.

  • Owner의 역할 선택에는 Admin·Member가 보이고 두 초대가 각각 성공한다.
  • Admin의 역할 선택에는 Member만 보이며 Member 초대는 성공한다.
  • Admin→Admin 선택 시도와 직접 API 요청은 초대·멤버십 데이터 변경 없이 거부된다.
  • Member에게 초대 CTA를 노출하지 않고 직접 경로·API 요청도 데이터 변경 없이 거부한다.
  • 초대 역할 선택과 기존 멤버 역할 편집을 같은 권한으로 처리하지 않는다. DEC-TRD-006의 초대 역할 행렬을 SC-29의 역할 변경 목적값·대상 제약으로 재사용하지 않는다.
  • Admin은 새 Admin 초대를 만들 수 없지만 SC-29에서 기존 Member를 Admin으로 승격하고 비-Owner·비자기 멤버를 조직에서 제거할 수 있다.
  • 이 화면에는 어떤 역할에도 자기 역할 변경·조직에서 제거·워크스페이스 나가기 CTA가 없고 초대와 자기 이탈을 같은 흐름으로 처리하지 않는다.
  • 이메일, 역할, 현재 초대 상태, 버튼명, 만료 시각, 오류 문구를 기록하고 이메일 전송 요청과 상대방 수락 완료를 분리한다.
