접근 Owner/Admin/Member가 본인 담당 또는 공동 작업자로 내부 공유된 모든 유형의 문서를 작성·수정·Confirm. Approval 행동은 향후 활성 모드에서만 해당 권한 적용

이 화면은 공통 UI 품질 계약의 반응형·locale·접근성 기준을 상속한다. 모바일에서도 단일 발행 문서의 작성·편집·저장·Confirm·오류 복구를 끝까지 완료할 수 있어야 하며, 공식 지원 locale 모두에서 키보드와 스크린 리더로 같은 단계와 상태를 확인·실행할 수 있어야 한다.

QA 기준

이 절은 앞선 제품 계약을 검증하기 위한 점검 항목이며, 독립적인 제품 요구사항을 추가하지 않는다.

생성·수정·Confirm·Job history 단계를 구분하고 문서 종류, Deal, 필드 표시명, 누른 버튼, 새 버전, 변경 근거와 오류 문구를 기록한다. Pilot에서는 승인 요청·승인·승인 대기 UI가 노출되지 않는지 확인한다. Approval 모드가 활성화된 경우에만 승인 단계를 별도로 검증한다.

현재 Frontend의 승인 상태와 CTA는 Pilot 기본 비노출 정책과 충돌하는 IMPLEMENTATION_GAP이다. Backend 승인 API·상태·사건 계약은 보존한다.
