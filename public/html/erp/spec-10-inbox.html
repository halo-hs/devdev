이 화면은 공통 UI 품질 계약의 반응형 범위를 상속한다. 모바일에서도 문서 상태·목록·빈 화면·오류·재시도를 안전하게 표시하고 단일 문서 열기와 단일 실패 재추출을 완료할 수 있어야 하며, 목록·표의 가로 스크롤은 해당 컨테이너 안에서만 제공한다.

목록·행동·호출

구역·상태 보이는 항목 버튼·행동 호출 성공·오류·복구
문서 목록 파일명, 문서 종류, 처리 상태, 수신 시각, Deal 맥락, 오류 사유 파일 업로드 문서 업로드·목록 조회 새 항목과 처리 상태 표시; 실패 파일은 오류 유지
문서 행 추출·검토·중복·실패 상태 문서 열기 최신 문서·추출 상태 조회 /erp/confirm/{documentId}
실패 행 사용자 언어로 쓴 실패 사유, 재시도 가능 여부 다시 추출 추출 재시도 새 작업 상태 표시, 실패 시 기존 결과 보존
삭제 가능 행 파일명, 미연결 상태 삭제 문서 삭제 성공 시 목록 제거, 실패 시 행 복원
은행거래내역서 행 파일명, 거래 연결 필요 상태 문서 열기 최신 문서·후보 조회 거래 연결 2단계로 진입; 같은 통화의 미결제 일정·금액·입금일 확인 후 연결
Deal 맥락 진입 from=deal, deal_id, expected_doc_type 업로드 같은 문서 API 업로드 뒤 Deal 연결 검토에 사용할 맥락 유지

시작 가이드 T1 variant

  • 일반 Inbox 진입·일반 파일 업로드는 변경하지 않고 popover를 자동 표시하지 않는다.
  • T1 체크리스트 CTA의 유효한 guide intent가 있을 때만 업로드 workbench로 scroll하고 실제 파일 선택 control에 focus한다. 브라우저 file picker는 자동으로 열지 않는다.
  • 안내는 최근 발주서(PO) 1건을 우선 권장하고, PO 번호·거래처·품목·수량·단가·납기가 보이는 PDF가 적합하다고 설명한다. 대체 문서는 매매계약서(SC)와 상업송장(CI)다.
  • 한 파일에는 한 업무 문서만 넣고 암호 없는 PDF를 권장한다. 최대 용량은 서버가 반환한 현재 허용값을 표시하며 이 문서에 숫자를 하드코딩하지 않는다.
  • 실제 문서 생성 성공과 quickstart document anchor 연결이 모두 성공해야 T1을 완료한다. 업로드 선택·전송 시작·guide 닫기는 완료가 아니다.
  • 생성 뒤 추출 처리·재시도는 Inbox가 소유한다. 성공 뒤 Inbox에 남고 T2가 준비되면 LNB의 이어하기 경로를 Confirm으로 갱신한다.

QA 기준

이 절은 앞선 제품 계약을 검증하기 위한 점검 항목이며, 독립적인 제품 요구사항을 추가하지 않는다.

거래 연결을 마친 문서가 검토·배정 대기 목록에서 제외되는지 확인한다. 은행거래내역서가 거래 연결 필요 상태로 진입하는지 확인한다. 파일명, 화면 상태, 업로드·추출 단계, 현재 실패를 만든 extraction_attempt_id 또는 레거시 확인 불가 상태, 행 유지 여부를 기록한다. 빈 목록과 목록 조회 실패를 구분한다. 식별자 의미와 보안·전환 규칙은 FS-01 추출 실행 식별자 계약을 따른다.
