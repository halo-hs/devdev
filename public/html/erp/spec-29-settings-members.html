SC-29 — 멤버 설정

CURRENT_LEGACY: 이 문서는 기존 /erp/settings의 Space 멤버 화면을 보존한다. 목표 Organization Member 화면과 권한은 Common CS-08이 소유한다. Trade OS App 사용자 화면 SC-45를 정의하거나 대체하지 않는다. 경계 반영: 2026-08-20.

결정 근거: DEC-TRD-011 — 기존 멤버 관리·자기 이탈 · 대체된 역사 기준: OPEN-017a · TRADE-DOC-001 — QA 절의 규범 경계

경계: ERP owner/admin/member 역할·제거 API는 현재 구현 역추적값이다. 신규 기획·화면·권한 정본으로 사용하지 않는다.

2026-07-31 결정 반영 — 아래는 확정 정책이다. 구현·QA 상태는 이 문서가 관리하지 않는다.

  • DEC-TRD-001 — 대손 확정·월 마감·edit_bank_profile은 capability·재인증·감사를 요구하고 기본값은 Owner/Admin 전용이다. 입출금·부분 입출금 기록과 대손 제안은 Member가 수행한다. 소규모 조직에 이중 승인을 강제하지 않는다.

멤버 관리 권한

멤버 관리는 새 초대와 별도 capability다. 초대할 때 선택할 수 있는 역할 범위를 기존 멤버의 역할 변경 Select에 재사용하지 않는다.

행동 Owner Admin Member
기존 멤버 역할 변경 비-Owner·비자기 대상에 Admin·Member 선택 가능 비-Owner·비자기 대상에 Admin·Member 선택 가능 화면 접근 없음; 직접 API 거부
기존 멤버 조직 접근 차단 비-Owner·비자기 대상 조직에서 제거 CTA 사용 가능 비-Owner·비자기 대상 조직에서 제거 CTA 사용 가능 화면 접근 없음; 직접 API 거부
자기 행 역할 배지만 읽기 전용; Select·저장·조직에서 제거·나가기 CTA 없음 동일 화면 접근 없음; 자기 이탈은 개인 설정에서 실행
Owner 변경 일반 역할 Select 대상 아님; 별도 소유권 이전 실행 불가 화면 접근 없음

조직에서 제거는 대상 조직의 멤버십을 삭제해 해당 조직의 ERP 접근만 차단한다. 사용자 계정·개인정보·다른 조직 멤버십은 유지하며 별도 blocked·suspended 상태나 차단 해제 CTA는 없다. 담당 업무 재배정과 보존 대상 데이터 처리를 먼저 확인하고, 같은 조직에 다시 접근하려면 새 초대를 수락해 멤버십을 다시 생성한다.

워크스페이스 나가기는 현행 화면의 레거시 명칭이며 이 화면의 멤버 관리 행동이 아니다. 목표 구조에서 본인의 Organization Membership 이탈은 Common CS-06의 `일반 > 소속 Organization`에서 실행하며, SC-29 자기 행에는 나가기 링크나 대체 CTA도 두지 않는다.

QA 기준

이 절은 앞선 제품 계약을 검증하기 위한 점검 항목이며, 독립적인 제품 요구사항을 추가하지 않는다.

  • Owner와 Admin에게 비-Owner·비자기 멤버의 역할 Select와 조직에서 제거 CTA가 보인다.
  • Owner와 Admin이 Member를 Admin으로 승격하고 기존 Admin을 Member로 변경할 수 있다.
  • Member에게 역할 Select·저장·조직에서 제거 CTA를 노출하지 않고 직접 API도 데이터 변경 없이 거부한다.
  • Member에게 멤버 탭과 직접 경로를 노출하지 않고 목록 조회도 거부한다. 개인 설정 /account/workspaces 접근은 별도 capability로 허용한다.
  • 화면에 진입한 Owner/Admin의 자기 행은 읽기 전용이고 역할 Select·저장·조직에서 제거·워크스페이스 나가기 CTA가 없다. Member는 이 화면에 접근하지 않으며 자기 이탈은 개인 설정에서 실행한다. Owner 변경은 별도 소유권 이전으로 처리한다.
  • 조직에서 제거하면 해당 조직 접근만 차단하고 사용자 계정·개인정보·다른 조직 멤버십이 삭제된 것으로 표시하지 않는다.
  • 제거된 멤버를 blocked·suspended 상태로 남기거나 차단 해제 CTA를 표시하지 않으며, 재접근은 새 초대·수락으로 검증한다.
  • 제거 모달에서 recall/transfer/per_deal, 모든 활성 Deal 영향, 조건부 이관 대상, 확인 문구를 표시하고 부분 이관·부분 삭제가 없다.
  • 역할 변경은 /admin/users/{user_id}/role, 제거는 /admin/members/{user_id}로 분리하고 자기 대상 호출은 403으로 무변경 거부한다.
  • 대상 사용자, 변경 전후 역할, 재배정 선택, 사유, 결과, 시각, request ID를 기록한다. 멤버 제거·자기 이탈·개인정보 삭제를 같은 행동으로 취급하지 않는다.

개발 역추적

member settings → members.ts, userPrivacy.ts → 역할 변경 PATCH /api/v1/admin/users/{user_id}/role, 조직에서 제거 DELETE /api/v1/admin/members/{user_id}, Owner-only export·erasure BFF → admin handler/service/data. 자기 이탈 API는 이 화면에서 호출하지 않는다.
