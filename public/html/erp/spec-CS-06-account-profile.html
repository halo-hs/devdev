추가 반영: 2026-08-26 무료체험 정책 — COMMON:DEC-TRIAL-001

화면 목적

Account 개인 설정, Organization 관리, Trade OS와 SNAP의 제품 설정을 한 허브에서 명확히 구분한다. Organization Member·구독·결제를 제품마다 중복하지 않는다.

Trade OS와 SNAP의 주 메뉴에서 설정을 선택하면 이 Common 설정 허브로 진입한다. Trade OS의 App 사용자는 제품 주 메뉴이며 이 허브의 메뉴가 아니다.

일반

내 계정

Account 프로필·인증 수단·로그아웃을 제공한다. Organization 역할·제품·결제 mutation을 두지 않는다.

소속 Organization

보이는 항목 행동
Organization명·본인 역할·활성 제품 상태 OrganizationContext 전환
대기 초대 초대 확인·수락·거절
새 Organization 생성 개수·플랜·운영 승인 제한 없이 명시적 생성
활성 Membership Organization Membership 자기 이탈

마지막 OWNER의 이탈은 차단하고 새 OWNER 등록·소유권 이전을 안내한다.

조직

조직 정보

현재 Organization의 기본 표시 정보를 모든 활성 Organization Member에게 읽기 전용으로 보여주고 OWNER에게만 변경을 허용한다. 계약·결제 상세는 아래 전용 메뉴에 두며 제품 업무 기본값은 제품 설정에 둔다.

사용자 관리

사용자 관리
├─ 조직 멤버 목록
├─ 멤버 초대
├─ OWNER / ADMIN / MEMBER 역할 관리
└─ 제품·메뉴 접근 권한 관리
  • OWNER는 OWNER·ADMIN·MEMBER와 제품·메뉴 접근을 관리한다.
  • ADMIN은 MEMBER 초대·변경·삭제와 MEMBER 접근만 관리한다.
  • 제품별 Workspace·제품별 멤버 관리 메뉴를 두지 않는다.
  • App User는 이 화면에 포함하지 않는다. App User 초대·아이디 등록·제품 관리자 지정은 Trade OS의 독립된 App 사용자 주 메뉴가 소유한다.
  • 접근 권한의 저장·판정 단위는 `COMMON:DEC-ACCESS-001`이 결정하기 전까지 구현에서 임의로 메뉴·화면·기능 중 하나로 고정하지 않는다.

제품 및 구독

Trade OS·SNAP 각각에 대해 trial 미시작 / trial 활성·무료 이용량 사용 가능 / trial 무료 이용량 소진 / trial 기간 종료 / 유료 구독 활성·비활성을 표시한다. Bundle도 제품별 행으로 풀어 entitlement를 표시한다.

  • OWNER: trial 시작, 구독·Plan 변경 등 서버 capability가 허용한 상업 행동
  • ADMIN·MEMBER: 비금융 제품 이용 상태와 Organization OWNER가 시작·구독할 수 있습니다 안내만 표시. 요청 발송 action 없음
  • trial 시작 전에는 서버 Offer의 기간·제한 무료 이용량·카드 등록/자동 결제 없음·종료 시 전체 잠금을 표시한다.
  • 제품별 정확한 무료 제공량·차감 기준·유료 구독 상품은 각 제품의 별도 구독·크레딧 정책을 참조한다.

결제 및 인보이스

  • 활성 OWNER에게만 표시한다.
  • Organization의 Paddle Customer를 서버에서 확인하고 목적 제한된 Paddle 상세 페이지로 연결한다.
  • OWNER 변경 시 Paddle Customer를 교체하지 않는다.
  • 별도 payer·billing contact·invoice recipient 역할을 표시하지 않는다.
  • ADMIN·MEMBER에게 portal mutation URL·결제수단·인보이스 상세를 노출하지 않는다.

제품 설정

  • Trade OS·SNAP 구획은 subscription_state=paid_active이거나 trial_state=active AND trial_quota_state=available일 때만 표시한다.
  • 제품 구획에는 업무·운영·사용량 설정만 둔다.
  • 조직 정보·Organization Member·초대·구독·Paddle 결제를 제품 구획에 중복하지 않는다.
  • Trade OS App User 관리를 제품 설정 구획에 넣지 않는다.
  • 같은 Organization이어도 제품 데이터와 설정을 자동 공유하지 않는다.

CURRENT_LEGACY와 migration

  • Trade OS legacy /erp/settings와 SNAP /settings의 조직·멤버·결제 탭은 최종 구획으로 분리·이관한다.
  • SNAP /workers는 Organization Member와 제품 사용자·현장 참여자 기능을 먼저 분리한다. Organization Member 기능만 Common으로 이관하고 전체 /workers 화면을 Common 설정으로 간주하지 않는다.
  • legacy /account/workspaces는 일반 > 소속 Organization으로 승계한다.
  • 기존 route를 유지하는 동안에도 사용자 표시는 Organization으로 하고 제품별 Workspace를 최종 개념으로 노출하지 않는다.

IMPLEMENTATION_GAP

  • 최종 메뉴 route와 공통 Organization selector
  • Organization 역할·제품/메뉴 권한 관리 API
  • Organization:Paddle Customer 1:1과 OWNER portal grant
  • legacy 설정의 단계적 이동과 redirect
  • 제품별 trial·Bundle 상태 projection
  • trial Offer 표시값·무료 이용량 상태·전체 잠금과 유료 전환 연결

QA

  • Organization 없음·복수 Organization·전환 중 상태를 확인한다.
  • 유료 제품 0개, trial 활성·무료 이용량 소진·기간 종료, Trade OS만, SNAP만, Bundle을 확인한다.
  • OWNER·ADMIN·MEMBER별 사용자 관리·제품·결제 메뉴와 API 거부를 확인한다.
  • 제품별 멤버 관리·Workspace 정보가 남지 않았는지 확인한다.
  • App User가 Organization Member 목록에 섞이지 않는지 확인한다.
  • 제품의 설정이 Common 허브로 진입하고 Trade OS App 사용자가 설정 밖 주 메뉴로 유지되는지 확인한다.
  • Organization 전환 뒤 이전 조직의 결제·제품·데이터가 보이지 않는지 확인한다.
