1. 문서 목적과 적용 범위

사용자 문제와 완료 결과

AI가 읽은 값과 사용자가 고친 값이 섞이면 사용자는 현재값도 AI가 검증했다고 오해한다. 완료는 원본 추출값·근거·AI 추출 신뢰도·현재값·사용자 수정이 구분되는 것이다.

4. 업무 규칙과 표시 기준

문서 검증 차단 경계

  • 차단 오류는 문서 종류별 필수값 누락·형식 오류, 금액·통화 불일치, 당사자·수취인·계좌 불일치, Deal 방향 충돌, L/C 명시 필수 조건 위반이다.
  • 신뢰도 낮음, 선택 필드 누락, 날짜·표기 차이, 근거 부족은 권장 확인으로 표시한다.
  • 차단에는 필드·비교 문서·원문 근거·해결 행동을 표시하며 AI 점수만으로 차단하지 않는다.
  • 은행 제출 전 미해결 차단은 0건이어야 한다. 권장 확인은 사용자가 확인했음을 기록하고 진행할 수 있다.

근거: OD-021.

화면 계약

  • 수정되지 않은 값: AI 추출값과 신뢰도/근거 표시
  • 수정된 값: 현재값을 주로 표시하고 “사용자 수정”을 명시
  • 원본 보기: AI 추출값, 근거, AI 추출 신뢰도
  • 사용자 수정값에 별도 검증이 없다면 AI 신뢰도를 새로 붙이지 않음
  • 신뢰도는 숫자/등급 설명과 함께 색상 외 수단으로 제공

공통 UI 품질 계약 적용

공통 UI 품질 계약에 따라 AI 신뢰도·검토 필요·차단 오류·완료 상태를 색상이나 아이콘만으로 전달하지 않고 텍스트 또는 동등한 접근 가능한 이름을 함께 제공한다. 사용자는 키보드로 상태 설명과 원천 근거에 도달할 수 있어야 하며, 화면 읽기 도구는 필드 이름·현재값·AI 추출값·근거·신뢰도·검토 상태의 관계를 구분해 읽을 수 있어야 한다.

근거: DEC-TRD-010.

꼭 지켜야 할 점

  • 사용자 수정이 원본 근거를 삭제하지 않는다.
  • 과거 데이터에 출처가 없으면 “알 수 없음/없음”으로 표시하고 추정하지 않는다.
  • AI 제공자·모델·버전은 사용자 화면에 표시하지 않는다.
  • 내부 성능 측정 결과가 사용자에게 보이는 신뢰도나 확정 결과를 바꾸지 않는다.
  • AI 실패와 업무 완료를 구분한다.
  • 필드 원천 근거의 제공자·모델·페이지 정보와 운영용 llm_call_logs는 다른 기록이다. 호출 로그에 행이 없다고 필드 근거가 없다고 판단하거나, 필드 근거만으로 모든 모델 호출이 운영 로그에 남았다고 판단하지 않는다.
  • 추출 실행 식별자의 의미·복사·레거시·권한·동시성 계약은 FS-01 추출 실행 식별자 계약을 따른다. 실행 ID는 필드 원천 근거나 운영용 llm_call_logs의 호출 ID를 대신하지 않는다.

다음 방식은 AI 신뢰도 표시로 사용하지 않는다.

  • 하나의 신뢰도를 사용자 수정 현재값의 신뢰도로 함께 표시
  • 사용자 수정 뒤 원본값·원천 근거를 삭제
  • 과거 데이터에 없는 근거나 신뢰도를 추정해 채우기

5. 현행 QA 점검 항목

이 절은 앞선 제품 계약을 검증하기 위한 점검 항목이며, 독립적인 제품 요구사항을 추가하지 않는다.

실제 통과 기준은 6~7장의 현행 구현 상태와 프론트·API·백엔드 원본 근거가 확인된 범위로 제한한다.

  • 미수정/수정/다시 추출/과거 필드가 각각 올바르게 표시된다.
  • 사용자 수정 현재값이 AI 고신뢰 값으로 오인되지 않는다.
  • 원본값/현재값 비교와 수정자/시각을 확인할 수 있다.
  • 키보드로 AI 상태 설명과 원천 근거에 도달할 수 있고, 화면 읽기 도구가 상태 관계를 구분하며, 색상 없이도 같은 의미를 이해할 수 있다.
  • 처리 요청/화면/내보내기의 값과 출처가 일치한다.
  • 여러 번 수정과 동시 저장에서도 이력이 보존된다.
  • OCR/비전 추출의 필드 근거가 존재해도 공통 LLM 호출 로그 포괄 여부는 별도로 확인한다.

6. 정책 및 구현 상태

구현 상태

플랫폼에는 신뢰도, 원문 페이지, 출처, 수정 정보가 존재하며 ERP에는 변경되지 않는 근거 화면의 강점이 있다. 현재값과 AI 추출 신뢰도의 의미 통합은 IMPLEMENTATION_GAP이다. OCR/비전 모델 호출은 현재 공통 LLM 호출 로그가 전부 포괄하지 않는다(CODE_GAP, TR-034). 추출 실행 식별자와 늦은 결과 fence는 아직 연결되지 않았다(CODE_GAP, TR-048).

오류별 표시와 복구 행동은 앞 장의 ‘화면 섹션별 흐름 상태표’에서 확인한다.

API·DB·감사

  • 원본값/현재값/출처/수정 정보를 명시적으로 응답한다.
  • 다시 추출은 새 출처 버전과 새 extraction_attempt_id로 관리하며, 대체된 실행의 늦은 결과는 현재 문서·필드 투영을 덮어쓰지 않는다.
  • 감사 기록은 수정, 되돌리기, 확정을 구분한다.
  • 내보내기에서도 현재값과 출처 의미가 화면과 일치해야 한다.

검증된 필드 개념은 필드 식별자/값, 신뢰도, 원문 페이지/근거/출처, 변경 이력이다. 현재값과 수정 정보는 여러 계층에 존재하지만 사용자 수정값이 원래 AI 신뢰도를 물려받는다고 해석해서는 안 된다. 다시 추출과 이력은 버전과 조직 범위를 유지한다.

현재 필드, 원문/페이지, 이력, 필드 변경은 각각 별도 처리 상태다. 과거 데이터에 출처가 없으면 “알 수 없음”으로 표시하며 신뢰도 0이나 가짜 근거를 만들지 않는다. 제공자/모델 실패, 근거 조회 불가, 오래된 수정, 내보내기 누락을 명시한다.

현재 판정: 변경되지 않는 근거/이력은 MATCH다. 화면/API/내보내기의 AI 추출값·현재값·신뢰도 의미 일치는 IMPLEMENTATION_GAP이다(TR-002/015). 제공자 공개와 재수탁자 최종 문구는 출시 전 DEFERRED 법무 확인이며 현재 기능 개발·내부 QA를 차단하지 않는다(LR-006).
