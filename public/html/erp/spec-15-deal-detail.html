생명주기 영향 확인

  • preview는 server cutoff 시각과 writer revision을 표시하고, 통화별 original_target, adjustment_net, current_target, applied, 받을 돈·지급할 돈 outstanding, 원본 입출금, surplus/prepayment, unresolved dispute, refund/return을 보여준다. 통화별로 분리하고 총액이나 FX 환산값을 만들지 않는다.
  • 완전한 근거로 계산된 0만 0으로 표시한다. {status: unavailable}은 “계산 불가”와 reason을 보여주며, 전체 coverage가 partial/unavailable이거나 actual cash가 unknown이면 단순 보관 CTA 대신 Owner/Admin 취소 영향 검토를 제공한다.
  • recorded에는 event 종류·방향·통화·가치일과 마스킹한 source reference를, none에는 검사 source·coverage 완료를, unknown에는 legacy/연결 불명/조회 실패 reason을 표시한다. 원문 계좌·문서·개인정보는 대화상자에 복제하지 않는다.
  • 모든 행동은 정해진 reason_code와 1~500자 note, 현재 상태, preview digest를 확인한다. 취소·재활성화는 “현재 집계는 바뀌지만 과거 금융·문서 이력은 유지됩니다” 확인 checkbox가 필요하다.
  • legacy imported 사건은 actor·시각·금융 근거의 unknown을 그대로 표시한다. 검증되지 않은 값으로 화면을 채우지 않으며 Member에게 legacy restore 실행을 노출하지 않는다.
  • stale 응답은 기존 사유 입력을 유지하고 “최신 영향 다시 확인”을 제공한다. 같은 idempotency key 재시도는 생성된 lifecycle event/receipt를 다시 표시하며 별도 성공 사건처럼 보이지 않는다.

직접 이동

이전 목록, /erp/documents?deal_id={dealId}, /erp/documents/create?deal_id={dealId}, /erp/inbox?from=deal&deal_id=..., 근거 문서 전달 화면으로 이동한다.

QA 기준

이 절은 앞선 제품 계약을 검증하기 위한 점검 항목이며, 독립적인 제품 요구사항을 추가하지 않는다.

Deal ID, 펼친 패널, 누른 버튼, 입력 사유, 호출 경로, 부분 실패 패널을 기록한다. 보관·취소·복원·재활성화 검증에는 직전 상태, actor, 통화별 예정금액 snapshot, 실제 현금 분류와 근거, preview revision/digest, 생성된 lifecycle event ID를 함께 기록한다. 한 패널 오류를 전체 Deal 없음으로 판단하지 않는다.

보관·취소 효력 시점부터 Deal은 현재 업무·재무 집계에서 제외하지만 원본 현금·정산·문서·분쟁 이력과 당시 snapshot은 읽을 수 있어야 한다. 복원·재활성화는 과거 snapshot을 수정하지 않고 새 사건의 효력 시점부터 현재 상태를 재계산한다. Member의 취소·재활성화와 recorded/unknown 현금 Deal의 단순 보관은 거부한다.

반복 archive/restore 또는 cancel/reactivate마다 lifecycle_sequence, cycle_no, cutoff, actor, reason과 새 snapshot이 증가하는지 확인한다. 동일 상태 행동과 허용되지 않은 전이는 INVALID_LIFECYCLE_TRANSITION, 금융 writer 변경은 LIFECYCLE_PREVIEW_STALE, 다른 Space Deal은 존재 여부를 구분하지 않는 DEAL_NOT_FOUND로 복구한다.

정산 상태는 OD-004를 따른다. 거래 방향이나 의무 정의가 미완료인 Deal을 정산 대상 아님으로 표시하지 않는다.

재무·정산 구역은 해당 Deal의 현재 잔액을 빠르게 확인하는 요약이다. 미수금·초과 입금·선수금·선급금의 원래 금액과 입출금·배정·환불·반환 전체 이력은 SC-21 정산의 원장 행 일정 상세 패널에서 확인한다. 별도 정산 상세 페이지는 만들지 않는다. 근거: OD-005 UI 위치.
