SC-35 — 구독·결제

CURRENT_LEGACY: 기존 /erp/settings/billing을 역추적하는 문서다. 목표 구독·결제·인보이스 화면과 OWNER 권한은 Common CS-06이 소유하며 Paddle 상세로 연결한다. Trade OS는 상품·플랜·사용량 정보를 제공한다. 경계 반영: 2026-08-20.

결정 근거: TRADE-DOC-001 — QA 절의 규범 경계

Common 목표 IA: 조직 > 제품 및 구독, 조직 > 결제 및 인보이스로 분리한다. 과거 OD-025의 Space·ADMIN 금융 조회는 현재 구현 호환 근거이며 신규 목표 권한이 아니다.

과거 결정의 승계 — 아래 Space 기반 상세는 CURRENT_LEGACY 구현·복구 계약이다. 목표 Organization 귀속과 Common OWNER-only 화면·권한은 이 문서 머리의 Common 계약을 우선한다.

  • DEC-BM-001 — 현재 플랜 크레딧과 추가 크레딧 가격은 상업 가설이다. unit economics·국가별 세금·고객 규제·upgrade motivation·fair use 검증 전까지 확정 가격으로 취급하지 않는다.
  • DEC-TRD-005 — 당시 Space 귀속과 legacy 재동의·invoice·provider 복구 계약. Space 귀속은 목표에서 Organization 1:1 호환 레코드로 이관한다.

CURRENT_LEGACY의 provider customer, 결제수단 binding, 구독, 인보이스는 Space에 속한다. 목표 귀속은 Organization이고 활성 OWNER만 Common을 통해 관리한다. Account 개인, 클라이언트 organization_id, Paddle customData, URL을 권한 근거로 사용하지 않는다. /erp/invoices의 무역 상업송장은 Billing 인보이스가 아니다.

구독 상태는 NOT_SUBSCRIBED/TRIALING/ACTIVE/PAST_DUE/PAUSED/CANCEL_SCHEDULED/CANCELLED/CONSENT_REQUIRED/PROVIDER_UNKNOWN이다. CONSENT_REQUIRED에서는 Owner 재인증·재동의와 provider 확인 전 mutation을 막고 검증된 Space 귀속 legacy invoice만 Owner/Admin에게 읽기 전용으로 제공한다. 모호한 invoice는 숨겨 support 사건으로 전환한다. PROVIDER_UNKNOWN도 mutation을 막고 재조회 행동을 제공한다.

Owner portal grant는 10분·1회용·목적 제한이며 역할·Space·구독 변경 또는 logout 시 철회한다. 업그레이드 요청은 Space+target당 하나만 활성화하고 24시간 중복을 합치며 30일 후 만료한다. provider event ID는 멱등 처리하고 webhook과 서버 재조회가 최종 상태를 확정하며 역순 사건으로 상태를 후퇴시키지 않는다.

없는 금융값은 null과 사유로 표시하며 0으로 바꾸지 않는다. invoice는 최신순 cursor pagination, Space-scoped detail/download ID, 10분·1회용 grant를 사용한다. inactive/suspended Space에서도 Owner/Admin 읽기와 Owner 복구는 유지하되 그 밖의 mutation은 차단한다. 요청 수락과 provider 성공을 분리해 표시한다.

QA 기준

이 절은 앞선 제품 계약을 검증하기 위한 점검 항목이며, 독립적인 제품 요구사항을 추가하지 않는다.

  • 전 역할의 허용된 비금융 제품 상태와 OWNER-only 금융·인보이스·상업 변경이 Common 메뉴·직접 URL·API에서 같다.
  • ADMIN·MEMBER는 금융·인보이스·결제 포털 session을 얻지 못한다.
  • OWNER는 현재 Organization의 인보이스만 Paddle에서 조회하며 다른 Organization·만료 링크·알 수 없는 역할은 데이터 변경 없이 거부된다.
  • 역할 거부, 상품 미구독, 결제 상태, 제공자 실패를 구분하고 외부 창 열기를 결제 성공으로 표시하지 않는다.
  • 인보이스 상세·내려받기와 변경은 실행자·현재 Space·capability·대상·결과·시각을 감사하되 결제정보·원문 인보이스를 로그에 남기지 않는다.

개발 역추적

현재 Owner/Admin 공용 화면·정적 Paddle 포털과 고객 Billing 전용 서버 API 부재는 CODE_GAP이다. 목표 연결은 Organization의 제품 상태와 OWNER-only Paddle 상세·mutation/session, 제공자 웹훅 재조회다.
