# 정산·성과 피드백 반영 및 서버 연결 경계

## #12 문구 결정
- 다시 조회 / 받을 돈 적용액 / Top N 표기를 사용한다.
- 결산 리포트와 영업성과 모두 거래 전체 손익이 마지막 받을 돈 만기일이 속한 달에 집계된다는 기준을 별도 설명으로 노출한다.
- 산식, 기간 필터, API 집계 데이터는 변경하지 않는다.

## #15 거래처 상태
- 기존 거래처별 금액 열을 유지하고 상태 열을 추가한다. 좁은 화면에서는 가로 스크롤한다.
- 연체·미정산 금액과 상각 근거를 구분한다. 상각 근거가 없으면 정산 완료를 추정하지 않는다.
- 현재 counterparty-status 계약에는 상각 합계가 없다. 표시 계층의 선택 필드 written_off_total은 서버 계약 확정 후 연결해야 한다. 미제공 시 상각 확인 필요로 표시한다.

## #33 정산 예외
- 예시 모드에서만 초과금 1,000을 임시 생성하고 환불·다른 일정 배정을 localStorage에 저장한다. 실제 원장·상단 집계의 금액을 변경하지 않는다.
- 실제 배정 API가 없으므로 일반 연결 모드에서는 배정 실행을 제공하지 않는다. 연결할 API: 거래처·통화·방향이 일치하는 대상 일정, 배정 명령, 배정 이력, 최신 잔액. 서버에서 권한·마감·잔액·중복 검증이 필요하다.
- 환불 전 요청 내용을 보존하고 결과 불명확 시 재전송을 차단한다. 새 환불 이력에서 같은 요청이 확인되어야 잠금을 해제한다. 운영 연결 시 요청 식별자/멱등키와 서버 결과 조회 계약이 필요하다.
- 인증·거래처·통화·마감·중복·검증 실패 안내를 구분한다.
- 빈 결정 카드 영역은 숨기며, 정산 대화상자는 390px 화면 내부에 맞추고 넓은 표는 가로 스크롤한다.

검증: npm run build, finance-feedback Playwright 5개(390px 포함), 변경 파일 ESLint 검사에서 기존 SettlementConnected의 react-hooks/set-state-in-effect 경고성 오류 1건이 남아 있다. 이번 변경과 무관한 기존 조회 효과는 유지했다.
