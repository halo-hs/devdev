# 본인 계정 탈퇴 — CS-22~25 프로토타입

2026-10-19. 사용자가 지정한 로컬 화면 명세 CS-22, CS-23, CS-24, CS-25를 읽고 반영했다. 원본 명세는 수정하지 않았다.

## 화면 위치

- `설정 > 일반 > 내 계정 > 계정 탈퇴`
- devdev 주소: `/erp/settings?section=account` (SNAP도 같은 공통 설정을 사용).
- 명세의 제품 프론트 주소 `/account/profile`에 해당하는 **기존 devdev 계정 화면** 안에서 상태를 전환한다. 별도 메뉴나 단계별 라우트는 추가하지 않는다.
- 소속 Organization 보기는 기존 설정의 `section=organizations`로 이동한다.
- `비밀번호 재설정으로 이동`은 기존 `/password-recovery`, 결과의 로그인 이동은 기존 `/login`을 사용한다.
- devdev에는 독립된 기존 계정용 조직 생성 경로가 없어 CS-22 안의 조직명 입력 화면으로 연결했다. 조직 생성 응답 뒤 전체 소속을 재조회하며, 생성 결과가 불명확하면 재조회하도록 한다. 신규 가입을 다시 요구하지 않는다. 실제 제품에 통합할 때는 명세의 기존 Organization 생성 동선에 연결한다.

## 화면 계약

| 단계 | 반영 내용 |
| --- | --- |
| CS-22 | 전체 소속 조회 중 / 소속 있음 / 소속 없음 / 조회 실패. 역할과 관계없이 활성 소속이 있으면 진행 불가. 조직 이름과 본인 역할 표시. 조직 없음일 때만 새 조직 만들기·탈퇴 계속. 초대는 메일 링크 안내만 제공. |
| CS-23 | 확인된 로그인 방식 한 가지만 표시. 비밀번호 확인 또는 Google 확인. 오류·취소·다른 계정·수단 불명 차단 및 재시도. 비밀번호 재설정 전 처음부터 다시 시작해야 함을 안내. 비밀번호는 확인 요청·오류·취소·화면 이탈 시 제거. |
| CS-24 | 접근 종료, 조직 기록 유지 및 개인 이름 비표시, 복구 불가, 재가입 시 권한 미복원. 법정 보관 안내와 조직 삭제·구독 해지와 별개임을 표시. 중복 제출 차단. 소속 생성/조회 실패와 재인증 만료에 맞는 단계로 복귀. |
| CS-25 | 접수 / 처리 중 / 완료 / 일부 실패 / 접수 불명을 분리. 결과 화면은 제품 내비게이션을 사용할 수 없는 전체 화면으로 표시. 접수 불명은 같은 요청 결과 조회만 허용. 명시적인 미접수 응답을 받은 경우에만 같은 요청 식별자로 재제출. 복원·접수 후 취소 없음. |

## 검토용 진입 링크

기본값은 소속 조직이 있는 계정이다. 아래 쿼리는 **프로토타입 응답 시나리오 선택**이며, 인증 완료나 중간 단계로 바로 진입시키지 않는다. 모든 링크에서 `계정 탈퇴`를 눌러 처음부터 진행한다. 페이지 새로고침은 내 계정으로 돌아간다.

공통 경로: `/erp/settings?section=account&withdrawalPreview=값`

| 값 | 검토 화면 |
| --- | --- |
| `member` (기본) | 소속 있음, 역할에 상관없이 탈퇴 차단 |
| `password` | 소속 없음 → 비밀번호 → 영향 안내 → 처리 중 |
| `google` | 소속 없음 → Google → 영향 안내 → 처리 중 |
| `membership-error` | 전체 소속 최초 조회 실패, 다시 확인 후 조직 없음 |
| `method-unknown` | 인증 수단 불명, 다시 확인 후 비밀번호 |
| `password-error` | 첫 비밀번호 확인 실패, 재입력 후 통과 |
| `google-cancelled` / `google-mismatch` | 첫 Google 확인 취소 / 다른 계정, 다시 확인 가능 |
| `auth-error` | 첫 재인증 오류, 재시도 가능 |
| `accepted` / `completed` / `failed` | 최종 제출 뒤 접수 / 완료 / 일부 실패 |
| `result-unknown` | 최종 제출 뒤 접수 불명. 첫 재조회도 불명, 다음 재조회로 처리 중 확인 |
| `not-received` | 접수 불명. 재조회 두 번째에 미접수 확인, 재제출 가능 |
| `membership-added` | 최종 제출 시 새 소속 발견 → CS-22로 복귀 |
| `membership-recheck-error` | 최종 제출 시 소속 조회 실패 → CS-22 오류 |
| `reauth-expired` | 최종 제출 시 재인증 만료 → CS-23으로 복귀 |

검토용 비밀번호 입력은 비어 있지 않은 임의의 값으로 진행한다. 실제 계정 비밀번호를 사용할 필요가 없다. Google 버튼도 외부 OAuth를 실행하지 않는 메모리 응답이다. 사용자 화면에는 시나리오 스위치나 구현 설명을 추가하지 않았다.

## 실제 API 연결 경계

`withdrawal-data.ts`의 `WithdrawalGateway`는 UI 어댑터 인터페이스이며 공개 HTTP API 계약이 아니다. URL, 개인정보 보존기간, 서버 인증 유효기간을 새 정책으로 정의하지 않았다.

현재 기본 어댑터는 메모리 예시 응답만 사용한다. 실제 계정 삭제, 조직 생성, Google 인증, 세션 철회, 이메일 발송을 수행하지 않는다. 입력값·재인증 상태·탈퇴 단계는 URL/localStorage/sessionStorage에 기록하지 않는다.

서버 연결 시 필요한 보장:

- 선택 조직에 한정하지 않은 전체 활성 Membership 조회.
- 확인된 계정 ID·로그인 수단·실제 재인증 시각 판정. UI 입력 완료만으로 재인증 승인 금지.
- 최종 접수 시 Membership·본인 계정·재인증 유효성 재검사.
- 중복 접수 방지 및 같은 요청 결과 조회, 새로고침/재접속 후에도 미결 요청 복구. 클라이언트의 메모리 UUID만으로 보장했다고 간주하지 않는다.
- 접수 후 실제 인증 접근 차단·세션 철회. 프로토타입의 전체 화면 결과와 내비게이션 차단은 서버 인증 차단을 대신하지 않는다.
- 실제 비동기 단계 완료 검증 뒤에만 완료 표시 및 확인된 이메일로 통지. 부분 실패 재처리는 같은 요청으로 운영에서 처리.
- 조직 귀속 기록 보존, 개인 식별정보 비표시·법정 보관 등은 서버 정책으로 처리.
