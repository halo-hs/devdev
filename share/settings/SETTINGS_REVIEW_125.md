# 설정·거래처 360 시안 결정 (#125)

2026-10-19 · 대상: halo-hs/devdev

## 화면 결정

1. **파일 일괄 등록**: 거래처·거래 등록 권한을 각각 판단한다. 메뉴와 직접 URL은 동일한 권한 값을 사용한다. 권한이 없으면 메뉴를 숨기고, 직접 접근은 기존 결재 정책과 같은 제목·이유 한 줄의 접근 불가 화면으로 표시한다. 멤버도 권한이 있으면 볼 수 있다.
2. **이메일 제한**: 메일당 첨부 개수, 첨부 한 개의 최대 크기, 허용 형식을 응답값으로 표시한다. 한 항목이라도 없거나 조회에 실패하면 숫자를 대체하지 않고 `제한 확인 필요`와 `다시 조회`를 표시한다. 메일 전체 크기는 첨부 크기로 사용하지 않는다.
3. **결재 정책**: 기존 설정의 24px 제목·설명·구역 카드 틀을 사용한다. 구역 제목과 설명은 카드 밖에 둔다. 조건·저장 흐름과 OWNER 접근 정책은 유지한다.
4. **보낸 초대**: `멤버 초대` 펼침 영역 안에서 이메일·역할·상태·만료 시각을 표시한다. 링크는 복사로만 제공한다. 재발송은 링크와 만료 시각을 갱신하고, 취소는 행을 `취소됨`으로 남긴다. 수락 전에는 멤버·구매 시트·배정 수를 늘리지 않는다. 빈 목록·만료·복사 실패·갱신 실패 상태도 제공한다.
5. **거래처 360**: 금액과 미결제 일정은 `담당·공동 작업 기준` 또는 `회사 전체 기준`을 표시한다. 멤버의 전체 조회 권한이 있으면 회사 전체 기준을 사용한다. 결제 신뢰는 모든 역할에서 회사 전체 기준이다. 회사 전체 조회를 원하는 멤버에게는 금액 아래 `회사 전체 금액·일정 조회는 조직 소유자에게 권한을 요청하세요.` 한 줄을 둔다. 통화의 작은 글자와 연체 금액의 일반 글자색은 유지한다.

## 시안 데이터와 서버 연결 경계

이 저장소의 해당 화면은 공개 디자인 시안이다. 이 변경으로 운영 서버에 새 API가 구현되거나 실제 메일이 발송되는 것은 아니다. 화면에 별도의 예시 안내 문구는 추가하지 않는다.

- `SettingsHubV2.permissions`: `canImportCounterparties`, `canImportDeals`를 입력받는다. 권한 객체가 전달됐는데 값이 없으면 허용하지 않는다. 역할별 기본값은 시안에만 사용한다. 운영에서는 인증된 서버 권한 응답을 전달하고, 등록 API에서도 권한을 검증해야 한다.
- `SettingsHubV2.loadEmailLimits`: 서버 조회 함수를 주입하는 자리. `{ maxAttachmentCount, maxAttachmentBytes, acceptedFormats, maxMessageBytes? }`는 이 시안의 화면 모델이며 확정 서버 JSON 필드명이 아니다. 현재는 별도 예시 응답을 표시한다. 조회 실패 때 예시값으로 폴백하지 않는다.
- 보낸 초대: `SettingsDemoProvider`의 예시 목록과 기존 `prototypeBackend.settings.resendInvite/cancelInvite` 로컬 어댑터를 사용한다. 링크와 만료 시각의 시안 갱신을 확인할 수 있다. 운영 연결에서는 서버가 발급·회수한 링크, 상태, 만료 시각을 받아 표시해야 한다. 기존의 미연결 신규 초대 실패 처리는 유지한다.
- 거래처 360: `CounterpartyPrototype.access`와 `counterpartyPreview.read`가 권한/범위를 받아 시안을 반환한다. 시안의 담당자·공동 작업자 예시로 거래를 한정하고 같은 일정에서 금액을 산출한다. 회사 합계를 멤버 합계로 재사용하지 않는다. 운영 연결에서는 서버에서 이미 권한 범위를 제한한 금액·일정·문서·거래 응답을 사용해야 한다. 프론트 역할 필터는 서버 권한 검증의 대체가 아니다.

실제 서버의 권한 키·메일 제한 응답·초대 API 경로는 이 이슈에서 확정하지 않았다. 다른 저장소에 접근하거나 API 경로를 임의로 추가하지 않는다.
