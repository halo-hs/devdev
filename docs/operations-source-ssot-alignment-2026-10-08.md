# 정산·운영 감시·결산 리포트·영업 성과 원문 및 기획서 대조

> 이 문서는 최초 대조 시점의 기록입니다. 이후 원본 리비전·문구 변경은 [전체 변경 목록](./ui-copy-changes-2026-10-08.md), 월마감 예시 동작과 PR 통합 범위는 [통합 내역](./release-integration-2026-10-08.md)을 기준으로 확인합니다. 아래 로컬·미배포 및 예시 응답 누락 설명도 최초 점검 당시의 상태입니다.

원본 한국어 메시지 908개를 문서 UI와 대조하고, 기획서의 역할·손익 기준·상태 문구 충돌을 정정했다. 이 기록은 로컬 변경과 확인 범위를 설명하며 전체 기능 동등성이나 배포 완료를 뜻하지 않는다.

### 테이블 문구 후속 대조

열 제목의 메시지 키와 실제 연결 코드를 함께 비교했다. 정산 원장·거래처 요약·점수표·독촉·송장 손익·집계 표, 운영 감시 처리량·운영 현황·예외 센터, 결산 마감 스냅샷·일정 대사, 영업 성과 거래처 표가 대상이다. 날짜 구간의 `–`, `+`, `AR/AP`, `Deal` 등 원문의 기호·영문도 유지한다.

운영 감시 표가 별도로 소비하는 `erpCommon.platformNav.monitorOps`는 원본과 같았다. `erpDeals.exceptionCenter`에는 대체 문구 4개, `erpDeals.detail.view.risk`에는 일수 차이 문구 2개가 빠져 있어 추가했다. 이 6개는 위 네 파일의 908개 집계에 포함하지 않는다. 원본의 리스크 이름·심각도·상세 표시 함수를 문서 UI로 옮겨 [예외 센터](../trade-os/operations/monitor/ExceptionCenter.tsx)에 연결했다.

- 미등록 코드: `기타 확인 항목`; 여러 개면 코드 정렬 순서로 번호를 붙인다. 알 수 없는 심각도는 `리스크`다.
- 상세: `+3d` → `3일 지연`, `-2d` → `2일 빠름`, `+10` → `차이 +10`, `-2.5` → `차이 -2.5`. 0일·빈 값·서버 자유 문장은 `—`다.
- 브라우저: 정산·영업 성과의 실제 열 제목을 확인했다. 예외 센터의 7가지 행 사례와 결산 스냅샷의 2개 표는 테스트 데이터로 1440/390 폭에서 확인했다. 예외 없음 안내도 확인했다. 원본 코드와 메시지 대조를 모든 서버 상태의 브라우저 검증으로 해석하지 않는다.
- 현재 기본 예시 데이터에는 마감 상세 응답이 없어 해당 상세가 로드 오류로 표시된다. 스냅샷 표 문구 검증에는 브라우저 안에서만 별도 응답을 주입했으며, 기본 예시 데이터나 실제 서버 기록은 변경하지 않았다.

이 후속 수정은 기존 원문 일치 결정의 UI 누락 보완이다. 제품 계약을 바꾸지 않으므로 새 SSOT 결정은 추가하지 않았다.

## 검증 범위

- 문구: 원본과 UI의 네 JSON 전체 값 일치, 기획서의 표시 문구 표 128행 일치.
- 문서: 변경 대상 본문·결정 문서의 상대 링크 및 앵커 119개, 6개 본문의 가까운 색인 역참조 확인. 전체 의사결정 원장 T1 검사를 통과했다는 의미는 아니다.
- UI 빌드: `npm run build` 통과. 기존 Lottie eval 및 큰 chunk 경고는 남아 있다.
- ESLint: 변경한 영업 성과·리포트·차트·운영 감시 API·표시 모듈의 지정 검사 통과. 저장소 전체 lint 통과 판정은 하지 않았다.
- 테이블 후속 검사: 예외 센터와 리스크 표시 함수 3개의 ESLint 및 UI 빌드 통과. 공유 표 메시지와 날짜 차이 문구도 원본과 일치한다.
- 브라우저: Chrome 예시 데이터 환경에서 네 화면 Owner의 1440/390 폭, 영업 성과 Member의 1440/390 폭을 확인했다. Member는 브라우저 응답에서 예시 역할만 치환했고 제품 원본·서버 권한은 변경하지 않았다.
- Member 영업 성과: 설명·조직 전체 기준·4개 KPI·준비 중 2개·월별 수취 예정/수금 적용·거래처 제한 안내 확인. 3개월 선택 후에도 담당자 파라미터 없이 settlement-series만 요청하며 GP·거래처 상태 요청은 없었다.
- 운영 감시 시각: 현재값, 미래 5분 경계, 5분 초과 거부, 서버 시각으로 미래 규칙 우회 금지, 15분 경계, 오래됨, 잘못된 날짜·누락 등 8개 경계 검사 통과.

## 남은 확인 사항

1. 원본 서버와 문서 UI를 같은 실제 응답으로 비교하는 live parity는 이번 점검에서 실행하지 않았다. 예시 응답의 필터 선택은 실제 서버 재집계·쓰기 성공 증거가 아니다.
2. 영업 성과 원본의 영역별 부분 실패·개별 재시도와 문서 UI의 묶음 조회는 추가 기능 대조 대상이다. 문구 일치만으로 이 차이를 해소했다고 판단하지 않는다.
3. 실제 정산 저장·발송·월마감·재개방·내보내기 및 전체 역할의 서버 거부 시험은 이 읽기·문구 검증 범위에 포함하지 않는다.

## 작업 기준의 충돌 처리

원본 `AGENTS.md`에는 devdev 문구를 우선하는 기존 지침이 있다. 이 지침을 두 저장소에 교차 적용하지 않도록 문서 UI의 [작업 지침](../AGENTS.md#운영성과-네-화면의-원본-대조-기준)과 제품 SSOT에 이번 네 화면의 적용 방향을 명시했다. **원본 리비전 → 문서 UI·SSOT** 방향이며, 이 범위의 원문·필터·기능은 `TRADE:OD-047`을 따른다. 제품 원본 저장소의 지침 자체는 수정하지 않았다.

과거 전면 점검 계획·9월 실행 계획·Pilot UX 제안은 현행 참조에서 제거했다. 원본 BFF 수정이나 기능 제거 제안을 현재 네 화면에 적용하는 근거로 쓰지 않는다. 현재 참조는 [문서 색인](./README.md)에서 확인한다. 개발자가 보고한 개별 충돌과의 동일성은 해당 문장·이슈가 있어야 확인할 수 있다.

제품 원본 저장소의 작업 트리는 변경하지 않았다. 변경은 문서 UI와 제품 기획 문서의 로컬 작업 트리에 있으며 커밋·배포하지 않았다.
