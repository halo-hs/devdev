# HTML 버튼·상태 화면 누락 점검 — 2026-09-16

후속 보완: [화면·버튼 연결 참조](html-interaction-links.md). 아래 집계는 보완 전 `2385a3a` 기준의 점검 기록입니다.

현재 HTML 공유본에는 앱에서 동작하지만 결과 화면으로 이동하지 못하는 버튼이 남아 있다. 특히 첫 화면에서 한 번 클릭한 상태 이후의 조작, 역할에 따른 승인 처리, 선택값에 따라 활성화되는 버튼이 빠졌다. 아래는 **점검 결과**이며 화면 보완·재배포 내역이 아니다.

## 기준과 범위

- 기준: main `2385a3a09d5d7d7690ceb0649738105820dca7bf`, HTML 상태 376개.
- 비교: 해당 main과 앱 소스가 동일한 격리 빌드에서 실제 클릭 → 저장된 HTML에서 해당 버튼의 비활성화·링크 유무 확인. 작업 중인 로컬 앱 변경은 비교 대상에서 제외했다.
- manifest의 미연결 항목은 337개 화면에 2,433건이다. 여기에는 반복 버튼, 숨겨진 버튼, 다운로드 등이 섞여 있으므로 **2,433개의 결과 화면이 빠졌다는 의미가 아니다.**
- 캡처 당시 보이는 활성 버튼과 대조한 후보는 1,969건, 버튼명 336종이다. 업무 영역과 버튼명이 같은 후보를 묶어 419개 대표 조합으로 점검했다. 같은 이름을 가진 모든 행·역할·입력값의 조합을 전수 검사한 것은 아니다.
- 외부 요청 및 GET/HEAD 이외 요청은 브라우저에서 차단하고 로컬 샘플 상태만 조작했다.

## 추가로 관찰된 미연결 조작

대표 조합 자동 클릭에서 다음 상태 변화를 관찰했다. 이 목록은 화면 중복 여부와 후속 입력 조건을 더 확인해야 하는 후보다.

- 문서 올리기: 재추출 후 필드 변경 이력, PDF 페이지 목록·페이지 이동.
- 문서 만들기: 문서 유형, 항목 수정, 거래 변경, 승인 없이 진행, 승인자 선택, 문서 스타일·강조색, 품목 전체 삭제 후 되돌리기.
- 거래: 확인 항목 이동, 문서 보기, 거래 담당자, 활동 이력, 문서 고객 전달.
- AI에게 묻기: 조회 대상 옵션, 예시 질문 결과, 참조 자료, 재생성, 결과에서 거래·선적·문서로 이동.
- 설정: 사용자 역할 옵션, 멤버 초대 후 대기 상태, 저장 후 표시 변화.
- 처음 시작하기: 담당 역할·관심 업무 선택, 단계 이동, 완료 상태.
- 영업 성과: 기간·통화·담당자 필터.

드롭다운이 열리는 화면이 있더라도 각 옵션 선택 후 결과가 모두 있다는 뜻은 아니다. `option`, `menuitem`, 입력값 변경 등은 기존 버튼 수집 범위 밖에 있어 별도 상태 표가 필요하다.

## 원인

1. `scripts/export-erp-html.mjs:644`의 자동 수집은 `scan: true`인 최초 화면만 순회한다. 생성된 하위 화면의 버튼을 다시 따라가지 않아 두 번째·세 번째 단계가 빠진다.
2. `scripts/export-erp-html.mjs:403`의 수집 대상은 `button`, `role=tab`, 클릭 가능한 행이다. 옵션·메뉴 항목·입력값 변경은 일반적으로 포함하지 않는다. 행·체크박스·스위치는 후속 수집에서 다시 제외한다.
3. 페이지 이동 버튼도 명시적으로 제외한다. 확대·축소와 달리 페이지 이동은 실제 표시 데이터가 달라지는 조작이므로 업무 상태로 보완해야 한다.
4. `scripts/erp-document-flows.mjs`에 역할 예시는 있지만 Admin·요청자 상태의 `flowLinks`는 비어 있다. 복사 완료·첨부 추가 완료에서도 후속 연결이 비어 있다.
5. 기존 정적 검사는 존재하는 링크가 깨졌는지와 지정된 기본 흐름을 확인한다. 활성 버튼 전체의 결과 화면 커버리지는 검사하지 않아 링크 오류 0건이어도 상태 누락은 남는다.

## 보완 기준

`진입 화면 → 역할·기존 상태 → 버튼/입력/선택 → 결과 상태 → HTML ID → 다음 가능한 조작`을 기준으로 연결해야 한다. 우선 역할별 승인·재요청, 매직링크 후속 조작, 거래 편집·삭제 확인, 알림 일괄 선택, 페이지 이동을 보완하는 것이 적절하다.

저장·삭제·선택 결과는 실제 앱에서 재현한 상태를 저장하고, 조건 미충족 버튼은 비활성 상태를 유지한다. 로딩·스켈레톤은 완료 결과와 별도로 기록한다. 운영 이메일 발송·고객 공개 URL 등 앱에서 연결되지 않은 기능은 성공 화면을 임의로 만들지 않는다.

## 검사 한계

자동 비교는 클릭 후 180ms의 텍스트·선택값·입력값·URL 변화를 관찰했다. 토스트나 선택 강조도 변화로 잡힐 수 있으므로 관찰 건수를 독립 화면 누락 수로 해석하지 않는다. 변화 없음은 비동기 완료나 입력 조건이 필요한 경우도 포함하므로 미구현 판정이 아니다. 재현 실패·현재 비활성 항목 역시 확인 보류다. 역할별 승인과 공유 후속 6개 조합은 별도로 다시 재현해 결과를 확인했다.
