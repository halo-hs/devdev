# 전체 화면 모바일 대응 작업 체크리스트

## 1. 목적

현재 프로토타입의 데스크톱 업무 흐름과 기능을 유지하면서, 모바일에서는 좁은 화면에 여러 패널을 동시에 축소해 넣지 않고 현재 작업에 필요한 한 영역만 명확하게 보여준다.

기준 문서:

- `docs/all-menu-source-functional-checklist.md`
- `docs/erp-menu-expansion-plan.md`
- `docs/source-functional-checklist.md`
- `docs/deals-source-functional-checklist.md`
- `docs/screens/file-upload-screen-spec.md`
- `docs/screens/document-create-screen-spec.md`

이 문서는 모바일 구현 전 작업 범위를 고정하는 체크리스트다. 모바일 대응 과정에서 기존 기능, 권한, validation, 자동저장, 상태값 및 화면 간 이동을 제거하지 않는다.

구현 확인: 2026-07-15 · Playwright로 `390x844`, `768x1024`, `1440x1000` 검증

## 2. 공통 모바일 원칙

### 2.0 반응형 구간

웹에서는 `dp`와 같은 의미로 CSS pixel 기준을 사용한다. Tailwind 기본 breakpoint와 맞춰 별도 숫자를 난립시키지 않는다.

- `0~479px` · compact mobile: `390px`을 대표 기준으로 사용한다. LNB를 숨기고 한 번에 작업 영역 하나만 표시한다.
- `480~767px` · large mobile: 모바일 구조를 유지하며 여백과 입력 폭만 확장한다.
- `768~1023px` · portrait tablet: 최대 2단까지만 허용한다. LNB는 icon rail 또는 Sheet로 전환하고 3단 문서 화면은 단일 작업 영역 전환을 유지한다.
- `1024~1279px` · landscape tablet/small desktop: 목록+본문 또는 본문+미리보기 중 최대 2단만 표시한다.
- `1280px 이상` · desktop: 파일 목록+필드+PDF 등 전체 3단 작업공간을 표시할 수 있다.

- [x] 컴포넌트 내부에서 임의의 breakpoint를 추가하지 않고 위 다섯 구간을 공통으로 사용한다.
- [x] `md`에서 데스크톱 구조를 그대로 축소하지 않는다.
- [x] 3단 레이아웃은 `xl` 이상에서만 활성화한다.
- [x] `390px`과 `768px`에서 각각 정보 우선순위와 작업 전환 방식이 명확히 달라진다.
- [x] 가로 overflow 검사와 별도로, 콘텐츠가 `overflow-hidden`에 의해 잘리지 않는지 시각 검증한다.

### 2.1 화면 구조

- [x] 데스크톱의 2단·3단 레이아웃을 모바일에서 가로로 축소하지 않는다.
- [x] 모바일 본문에는 현재 작업 영역 하나만 표시한다.
- [x] 목록은 바텀시트 또는 전체 화면 목록으로 연다.
- [x] 입력·검토 영역은 기본 본문으로 사용한다.
- [x] PDF 원문과 문서 미리보기는 전체 화면으로 전환한다.
- [x] 전체 화면 보기에는 이전 작업으로 돌아가는 명확한 버튼을 제공한다.
- [x] 화면을 전환해도 선택 문서와 입력값을 유지한다.
- [x] 패널과 Sheet는 공통 top bar 아래에서 시작하고 남은 viewport 높이 안에서 스크롤한다.
- [x] 모바일 Sheet는 전체 폭을 사용하되 제목과 닫기 버튼을 상단에 고정한다.
- [ ] 모달은 짧은 확인, 위험한 실행 확인, 권한 안내에만 사용한다.
- [ ] 페이지 안에서 직접 수정 가능한 업무는 모달로 옮기지 않는다.

### 2.2 공통 셸과 내비게이션

- [x] LNB는 햄버거 버튼으로 여는 전체 높이 내비게이션 Sheet로 전환한다.
- [x] 현재 메뉴명과 핵심 상태를 모바일 top bar에 표시한다.
- [x] 세계시간, 알림, 케밥 메뉴는 한 줄에서 겹치지 않도록 우선순위를 정한다.
- [ ] 세계시간과 알림 상세는 모바일 Sheet로 연다.
- [x] 메뉴 선택 후 LNB Sheet를 자동으로 닫는다.
- [ ] 브라우저 뒤로가기는 현재 작업의 내부 화면을 먼저 닫고 그다음 이전 페이지로 이동한다.
- [ ] safe-area inset을 상단과 하단 고정 영역에 적용한다.
- [ ] 키보드가 열렸을 때 Primary CTA와 현재 입력 필드가 가려지지 않는다.

### 2.3 버튼과 입력

- [ ] 터치 대상은 최소 44px 높이 또는 이에 준하는 충분한 클릭 영역을 확보한다.
- [ ] Primary CTA는 화면당 하나만 강조한다.
- [ ] 하단 고정 CTA는 본문 마지막 항목을 가리지 않도록 padding을 확보한다.
- [x] 아이콘 버튼에는 접근 가능한 이름과 tooltip 또는 대체 설명을 제공한다.
- [ ] 날짜, 금액, 수량, 통화, 단위 입력은 모바일 키보드 유형을 맞춘다.
- [ ] Select, Dropdown, Command 결과는 viewport 밖으로 잘리지 않게 위치를 계산한다.
- [ ] 자동저장 중, 저장 완료, 저장 실패 상태를 입력 흐름을 방해하지 않는 위치에 표시한다.
- [ ] validation 오류는 해당 필드 바로 아래에 표시하고 첫 오류로 이동할 수 있게 한다.

### 2.4 목록과 테이블

- [ ] 비교가 필요한 표는 핵심 열을 고정하고 가로 스크롤 또는 열 선택을 제공한다.
- [ ] 단순 목록은 compact List/Row로 전환한다.
- [ ] 모바일 목록 항목을 개별 Card 나열로 바꾸지 않는다.
- [ ] 행 선택은 배경, 체크 표시, 상태 라벨을 함께 사용한다.
- [ ] 검색, 필터, 결과 건수는 목록 위에서 한 덩어리로 유지한다.
- [ ] 필터가 많으면 핵심 필터만 노출하고 나머지는 필터 Sheet로 연다.
- [ ] 무한 스크롤은 로딩, 끝 도달, 재시도 상태를 표시한다.
- [ ] 케밥 메뉴가 화면 밖으로 잘리지 않고 행 선택을 방해하지 않게 한다.

### 2.5 PDF와 문서 미리보기

- [x] PDF와 생성 문서는 모바일 전체 화면 viewer로 연다.
- [x] 상단에 닫기 또는 필드로 돌아가기와 문서명을 표시한다.
- [x] 하단 floating control에 페이지 이동, 확대·축소, 화면 맞춤, 다운로드를 배치한다.
- [ ] pinch zoom과 두 번 탭 확대를 지원하거나 대체 확대 버튼을 제공한다.
- [ ] 확대 상태에서 가로·세로 스크롤이 문서 영역 안에서 동작한다.
- [ ] 원문 하이라이트 이동 후 해당 위치가 화면 중앙 근처에 보이게 한다.
- [ ] 전체 화면을 닫으면 이전 필드와 스크롤 위치로 돌아간다.

## 3. 3단 작업 화면 공통 전환

### 3.1 파일 올리기

데스크톱: `최근 파일 | 추출 필드 | PDF 원문`

모바일:

1. 기본 본문은 `필드 확인`이다.
2. 상단 문서명 또는 `최근 파일` 버튼을 누르면 파일 목록 바텀시트가 열린다.
3. `PDF 대조`를 누르면 PDF가 전체 화면으로 열린다.

- [ ] 최근 파일 바텀시트에 검색을 추가한다. 상태, 선택, 케밥, 삭제, 재시도는 구현됨.
- [x] 파일을 선택하면 바텀시트를 닫고 해당 필드 검토 화면으로 이동한다.
- [x] 업로드 영역은 파일 선택, 다중 업로드, 폴더, 수신 이메일 진입을 유지한다.
- [x] 업로드 진행과 오류 메시지는 업로드 영역 가까이에 표시한다.
- [x] 필드 입력과 AI 검증 내용은 한 열로 표시한다.
- [ ] 필드 수가 많아도 문서 헤더와 Primary CTA가 불필요하게 반복되지 않게 한다.
- [ ] 필수 필드 오류는 거래 연결 전에 해당 필드로 이동시킨다.
- [x] `필드 확인 → 거래 연결`은 같은 `파일 올리기` 작업공간 안에서 전환한다.
- [x] 거래 연결 화면에서 `PDF 대조로 돌아가기`를 제공한다.
- [ ] 실제 연결 완료 후 `거래에 첨부` 또는 `거래 보기`의 이동 결과를 명확히 구분한다.

### 3.2 문서 만들기 상세

데스크톱: `문서 정돈·요소 | 필드 확인 | 문서 미리보기`

모바일:

1. 기본 본문은 `필드 확인`이다.
2. `문서 요소`는 바텀시트로 연다.
3. `미리보기`는 전체 화면으로 연다.

- [ ] 방향과 문서 종류는 별도 단계 또는 상단 요약에서 수정할 수 있게 한다.
- [x] AI 검증 우선순위에서 오류 필드를 먼저 보여준다.
- [x] `필드 확인에서 보기`는 필드 화면으로 전환하고 해당 필드로 이동한다.
- [x] 품목 행 편집은 한 화면에서 품목명, 수량, 단가, 금액을 함께 확인할 수 있게 한다.
- [x] 품목 추가·삭제 후 현재 품목 위치와 저장 상태를 유지한다.
- [ ] 문구 다듬기는 필드 본문을 대체하는 전체 폭 편집 상태로 연다.
- [ ] 로고 선택은 조직 로고와 파일 업로드를 세로 목록으로 제공한다.
- [ ] 출력 스타일과 강조색은 미리보기 변화를 즉시 확인할 수 있게 한다.
- [x] 승인 요청, 반려 메시지, 승인 이력은 현재 문서 상태에 맞게 노출한다.
- [x] 문서 확정 후 확정 CTA를 숨기고 다음 행동을 고객 전달로 바꾼다.
- [ ] 고객 전달 Sheet와 고객 화면 미리보기 전체 화면을 구분한다.

## 4. 메뉴별 모바일 작업

### 4.1 처음 시작하기

- [ ] 단계 목록을 세로 진행 흐름으로 표시한다.
- [ ] 현재 단계만 펼치고 완료 단계는 체크와 요약만 표시한다.
- [ ] 파일 다중 업로드와 추천 거래처 검토가 한 화면에서 겹치지 않게 한다.
- [ ] 다음, 이전, 나중에 하기 CTA를 하단에 안정적으로 배치한다.

### 4.2 오늘 할 일

- [ ] 상단에 오늘 처리 건수와 가장 중요한 업무를 먼저 표시한다.
- [ ] 과도한 탭 없이 역할에 필요한 작업을 한 목록에서 우선순위로 보여준다.
- [ ] KPI는 가로 스크롤 카드가 아니라 2열 이하의 compact summary로 정리한다.
- [ ] 작업 행은 이유, 기한, 대상, Primary CTA를 세로로 읽을 수 있게 한다.
- [ ] 경영 브리프, 재무 인사이트, 운영 감시는 접을 수 있는 보조 섹션으로 둔다.
- [ ] 환율과 벤치마크 표는 핵심 환율 요약 후 상세 표를 펼쳐 보게 한다.
- [ ] AI 질문 입력은 화면 하단에서 키보드와 겹치지 않게 한다.

### 4.3 AI에게 묻기

- [ ] 질문 입력, 예시 질문, 결과를 한 열로 표시한다.
- [ ] 결과의 거래·문서·정산 근거 링크가 줄바꿈되어도 액션이 분리되지 않게 한다.
- [ ] 긴 답변에서 질문 입력으로 빠르게 돌아갈 수 있게 한다.
- [ ] 사용량, 인증, 서버 오류와 재시도를 모바일 폭에서 구분한다.

### 4.4 거래 목록

- [ ] 핵심 검색과 상태 필터를 상단에 유지하고 상세 필터는 Sheet로 연다.
- [ ] 데스크톱 표는 모바일 compact List/Row로 전환한다.
- [ ] 거래명, 거래처, 상태, 위험, 다음 작업을 우선 표시한다.
- [ ] 행 전체를 눌러 거래 상세로 이동하고 케밥은 독립 동작하게 한다.
- [ ] 필터·페이지·스크롤 상태를 상세에서 돌아왔을 때 복원한다.
- [ ] 거래 생성은 전체 화면 폼 또는 단계형 Sheet로 제공한다.

### 4.5 거래 상세

- [ ] 공통 top 아래에 거래명, 상태, 담당자, 핵심 CTA를 compact header로 표시한다.
- [ ] 개요, 서류 검증, 이행·선적, 재무·수익성, 관계자 탭은 가로 스크롤 가능한 sticky tab으로 만든다.
- [ ] 탭 전환 때 본문 폭과 스크롤 위치가 흔들리지 않게 한다.
- [ ] 서류 검증은 `연결 문서 → 문서 항목 → 원문 PDF`를 모바일 단일 화면 전환으로 바꾼다.
- [ ] 연결 문서는 바텀시트, 문서 항목은 본문, PDF는 전체 화면으로 제공한다.
- [ ] 항목 값과 출처 문서를 같은 행에서 확인할 수 있게 한다.
- [ ] 일정·수량·비용·정산의 입력 가능 값과 표시 전용 값을 구분한다.
- [ ] 거래 닫기, 미달 마감, 보관 등 위험 액션은 확인 Dialog로 실행한다.

### 4.6 선적

- [ ] 검색과 핵심 상태 필터를 sticky toolbar로 만든다.
- [ ] 거래별 그룹과 복수 B/L을 compact List/Row로 표시한다.
- [ ] ETA, D-day, 항로, 선박, 상태를 우선 표시하고 보조 값은 펼쳐 본다.
- [ ] 행 선택은 선적 상세로 이동하고 SNAP 근거는 별도 버튼으로 연다.
- [ ] 분할 선적과 컨테이너가 많을 때 내부 가로 스크롤 대신 세로 하위 목록을 사용한다.

### 4.7 정산

- [ ] `오늘 결정`을 최상단 목록으로 유지한다.
- [ ] AR/AP 방향, 만기, 잔액, 위험, 처리 CTA를 한 행에서 읽게 한다.
- [ ] 입금·지급 기록은 공통 top 아래에서 여는 모바일 전체 폭 Sheet로 제공한다.
- [ ] Sheet 제목과 닫기는 고정하고 입력 영역만 스크롤한다.
- [ ] 거래처별 AR/AP와 원장은 compact List 또는 핵심 열 표로 전환한다.
- [ ] 현금 흐름과 환노출 차트는 한 열로 쌓고 범례가 잘리지 않게 한다.
- [ ] CSV와 월간 명세서 다운로드가 입금·지급 CTA보다 강조되지 않게 한다.

### 4.8 운영 감시

- [ ] 활성 위험을 심각도 순 단일 큐로 보여준다.
- [ ] 예외 행에는 영향 거래, 금액 또는 일정, 담당자, 다음 액션을 표시한다.
- [ ] 예외 상세는 공통 top 아래에서 여는 모바일 전체 폭 Sheet로 제공한다.
- [ ] 처리하기, 담당자 지정, 거래 보기, 무시는 한 화면에 과도하게 강조하지 않는다.
- [ ] 처리 중, 이미 처리됨, 실패, 재시도 상태를 Sheet 안에서 유지한다.
- [ ] 차트는 한 열로 배치하고 터치 tooltip을 제공한다.

### 4.9 결산 리포트

- [ ] 기간 단위, 기간, 통화 필터를 모바일 한 줄 또는 필터 Sheet로 정리한다.
- [ ] KPI는 2열 이하로 표시하고 긴 금액이 잘리지 않게 한다.
- [ ] 차트는 한 열로 배치하고 범례와 축 라벨을 축약한다.
- [ ] 마감 가능 여부와 차단 요인을 차트보다 먼저 표시한다.
- [ ] `{period} 마감하기`는 공통 top 아래에서 여는 모바일 전체 폭 Sheet로 제공한다.
- [ ] 화면 높이가 작으면 마감 확인 내용만 내부 스크롤한다.
- [ ] 마감 CTA와 취소는 Sheet 하단에서 접근 가능하게 유지한다.
- [ ] 마감 스냅샷과 라이브 수치를 명확히 구분한다.

### 4.10 영업 성과

- [ ] 기간과 담당자·거래처 필터를 모바일 필터 Sheet로 제공한다.
- [ ] KPI와 추이 차트를 한 열로 배치한다.
- [ ] 담당자·거래처 성과 표는 순위형 compact List로 전환한다.
- [ ] 행 선택 시 성과 근거와 관련 거래를 별도 상세 화면 또는 Sheet로 연다.
- [ ] Pro 권한 차단과 업그레이드 안내가 실제 데이터처럼 보이지 않게 한다.

### 4.11 설정

- [ ] 설정 카테고리는 첫 화면 목록으로 표시하고 상세 설정은 다음 화면으로 이동한다.
- [ ] 조직, 멤버, 역할, 알림, 문서 기본값을 긴 한 페이지에 모두 쌓지 않는다.
- [ ] 저장 상태와 오류를 각 설정 섹션 가까이에 표시한다.
- [ ] 위험 설정은 확인 Dialog와 권한 검사를 사용한다.

## 5. 연결 화면 모바일 작업

### 5.1 거래처 360

- [ ] 요약, 거래, 문서, AR/AP, 활동을 한 열 섹션 또는 탭으로 정리한다.
- [ ] 긴 주소와 법인 정보가 KPI 영역을 밀어내지 않게 한다.
- [ ] 관련 거래와 문서는 compact List/Row로 표시한다.

### 5.2 SNAP 증거함

- [ ] 긴 원문, 해시, 출처 정보는 줄바꿈과 복사를 지원한다.

### 5.3 결제·구독

- [ ] 현재 플랜, 사용량, 결제 수단, 청구 내역을 세로로 분리한다.
- [ ] 플랜 변경과 결제 수단 변경은 전체 화면 또는 Sheet로 제공한다.
- [ ] Pro 기능 잠금과 결제 오류 상태를 구분한다.

### 5.4 토큰 사용량

- [ ] 기간·제품 필터를 상단에 두고 요약과 상세 사용량을 한 열로 표시한다.
- [ ] 제품별 사용량은 compact List 또는 가로 스크롤 가능한 최소 열 표로 제공한다.

### 5.5 고객 전달

- [ ] 고객 전달 Sheet는 모바일 전체 폭과 top 아래 높이를 사용한다.

- [ ] Magic Link 생성, 복사, 새 창 열기, 철회, 삭제를 터치하기 쉽게 배치한다.
- [ ] 이메일 받는 사람, 제목, 본문, 첨부 링크 선택이 키보드에 가리지 않게 한다.
- [ ] 고객 화면 미리보기는 전달 Sheet가 아니라 별도 전체 화면 viewer로 연다.

## 7. 반응형 검증 기준

필수 viewport:

- [ ] 360 × 800: 최소 폭 Android
- [ ] 390 × 844: iPhone 기준
- [ ] 430 × 932: 큰 모바일
- [ ] 768 × 1024: 세로 태블릿
- [ ] 1024 × 768: 가로 태블릿
- [ ] 844 × 390: 모바일 가로 모드

각 viewport에서 확인:

- [ ] 가로 overflow가 의도하지 않은 위치에 생기지 않는다.
- [ ] text, badge, button이 잘리거나 겹치지 않는다.
- [ ] 고정 top bar와 하단 CTA가 본문을 가리지 않는다.
- [ ] Sheet, Dialog, Dropdown, Select가 viewport 밖으로 나가지 않는다.
- [ ] 목록 선택, 입력, 자동저장, 뒤로가기, 전체 화면 복귀가 동작한다.
- [ ] PDF가 비어 있지 않고 확대·축소·다운로드가 동작한다.
- [ ] 차트가 비어 있지 않고 범례, 축, tooltip을 확인할 수 있다.
- [ ] 터치만으로 hover 전용 액션에 접근할 수 있다.
- [ ] 브라우저 콘솔 오류와 React hydration 오류가 없다.

### 7.1 2026-07-15 현재 구현 실측 기준선

Playwright로 `390 × 844`, `768 × 1024`를 확인한 결과다. 아래 항목은 모바일 구현 완료 전 해결해야 하는 현재 실패 상태다.

- [ ] `390px`에서 고정 148px LNB를 제거한다. 현재 오늘 할 일 제목과 설명이 글자 단위로 줄바꿈된다.
- [ ] `390px` 파일 올리기 첫 화면에서 제목, 업로드 영역, 이메일·폴더·파일 올리기 액션이 본문 폭 안에 모두 보이게 한다.
- [ ] `390px` 파일 상세에서 최근 파일, 필드 확인, PDF가 화면 밖에 남지 않도록 한 영역씩 전환한다.
- [ ] `768px`에서 고정 LNB를 축소하거나 Sheet로 전환해 본문 유효 폭을 확보한다.
- [ ] `768px` 파일 상세에서 PDF만 크게 남고 필드 확인이 사라지는 현재 레이아웃을 1~2단 작업 전환으로 바꾼다.
- [ ] `document.body.scrollWidth === innerWidth`만으로 통과 처리하지 않는다. 현재도 overflow 수치는 정상이나 콘텐츠가 잘려 사용할 수 없다.
