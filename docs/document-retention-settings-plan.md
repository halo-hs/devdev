# 문서 보관 정책 설정 계획

## 목표

- 거래가 삭제·중단·취소되어도 정산과 감사에 필요한 문서 이력이 사라지지 않게 한다.
- 거래에는 `최종 보관 필요일`을 한 번에 표시하되 원본 파일은 문서 유형별 보관기한으로 관리한다.
- 법정 최소기간은 관리자가 줄일 수 없고, 조직 정책에 따른 연장만 허용한다.

## 정책 원칙

1. 문서마다 `retention_until`을 계산한다.
2. 거래의 `final_retention_until`은 연결 문서 중 가장 늦은 날짜로 계산한다.
3. 거래가 삭제되면 소프트 삭제하고 문서·정산 이벤트·변경 이력은 보존한다.
4. 법적 보류가 설정된 문서는 만료일이 지나도 보류 해제 전까지 파기하지 않는다.
5. 개인정보는 별도 보유 근거가 없으면 목적 달성 후 파기하고, 감사에 필요한 최소 메타데이터만 남긴다.

## 설정 동작

- 적용 관할과 법정 최소기간은 시스템 기준값으로 표시한다.
- 조직 관리자는 문서 유형별로 0·1·3·5년을 추가할 수 있다.
- 최종 보관기간은 `법정 최소기간 + 조직 연장기간`으로 즉시 계산한다.
- 법적 보류 우선 적용을 켜거나 끌 수 있다.
- 보관 정책 변경은 정책 버전과 변경자를 기록하고 기존 문서에는 소급 적용 여부를 별도로 결정한다.

## 예외 처리

- 중단·취소 거래: 거래 상태가 아니라 문서 성격으로 보관기한을 계산한다.
- 여러 국가가 관련된 거래: 적용 가능한 정책 중 더 긴 법정 최소기간을 사용하고 근거를 남긴다.
- 문서 유형 미분류: 자동 파기 대상에서 제외하고 관리자 검토 큐로 보낸다.
- 정책 변경: 이미 만료된 문서를 자동 복구하지 않으며, 보관 중인 문서의 재계산 결과를 미리 보여준 뒤 적용한다.
- 법적 보류: 삭제·익명화·파기 작업보다 항상 우선한다.

## 구현 범위

- 이번 프로토타입은 설정 내비게이션, 문서 유형별 연장기간, 법적 보류, 저장 상태를 구현한다.
- 실제 운영 구현에서는 서버 정책 버전, 권한, 감사 로그, 파기 배치와 복구 불가 확인 절차가 추가로 필요하다.
