# 거래 상세 기능 및 입력·표시 구분 재점검

## 결론

거래 상세의 기본 화면은 **읽기 전용 운영 현황**이 중심이다. 거래 단계, 금액, 인코텀즈, 결제조건, ETA, AR/AP, GP, 서류 상태처럼 문서·거래·정산 데이터에서 계산되는 값은 입력박스로 만들지 않는다.

사용자가 실제로 변경할 수 있는 값만 입력 UI를 제공한다. 입력 UI도 항상 펼쳐두지 않고 `추가`, `편집`, `허용`, `마감`, `플래그` 같은 액션을 누른 뒤 로컬 폼·팝오버·다이얼로그로 연다. 예외적으로 검색, 담당자 선택, 노트 작성은 반복 빈도가 높아 화면에 상시 노출해도 된다.

## 2026-07-13 재점검 결과

- 위험 액션: 리스크 허용, 주문 상태 변경, 거래 삭제, 문서·연락처·공유 연결 해제에 확인·필수 입력·busy lock을 적용했다.
- 업무 폼: 원가, 당사자, 연락처, 공유 멤버 선택을 실제 입력 흐름으로 교체했다.
- 안전·신뢰: Owner/Admin/Member 권한, 은행계좌 변경 경고, 패널별 error+retry, 감사 이력을 적용했다.
- 조회: Confirm 필드 검색, GP 상태 판정, 통화별 버킷, SNAP 연결을 적용했다.
- 남은 범위: 전체 상세 loading, 느린 요청 event guard, 보관·복원, 하위 패널별 empty/error 샘플, URL 상태 복원이다.

현재 구현 판정의 SSOT는 `deal-detail-implementation-matrix.md`이며 아래 표의 입력·표시 구분 원칙은 그대로 유효하다.

## 판정 기준

| 구분         | 기준                                            | UI                                             |
| ------------ | ----------------------------------------------- | ---------------------------------------------- |
| 표시         | 문서·거래·정산·선적에서 파생되거나 서버가 계산  | 텍스트, 상태 배지, 표, 타임라인                |
| 상시 입력    | 상세 사용 중 반복적으로 검색·작성               | 검색창, 담당자 선택, 노트 입력                 |
| 액션 후 입력 | 변경 빈도가 낮거나 결과가 거래 상태에 영향을 줌 | 다이얼로그, 팝오버, 인라인 편집 폼             |
| 확인 액션    | 삭제·연결 해제처럼 별도 값은 없지만 영향이 큼   | 확인 다이얼로그                                |
| 권한 조건    | 원소스 write route가 Owner/Admin만 허용         | 일반 Member에는 입력과 버튼을 숨기고 값만 표시 |

## 1. 상단과 거래 360

| 항목                           | 원소스 성격              | 권장 UI                        | 현재 프로토타입                                  |
| ------------------------------ | ------------------------ | ------------------------------ | ------------------------------------------------ |
| Deal ID, 거래명, 거래처        | 표시                     | 제목·보조문구                  | 반영                                             |
| 거래 단계                      | 서버 상태                | 배지와 단계 진행 표시          | 배지만 반영, 계약→선적→통관→정산 파이프라인 누락 |
| D-day, 리스크 개수             | 계산                     | 배지·요약값                    | 반영                                             |
| 담당자                         | 변경 가능, Owner/Admin   | 상단 Select. 변경 중·실패 표시 | 역할 제한·저장 피드백·감사 이력 반영             |
| ETA, 받을 돈, 줄 돈, 선적 건수 | 계산                     | 4열 요약 표시                  | 반영                                             |
| 금액, 통화, 인코텀즈, 결제방식 | 문서/aggregate 파생      | 상업조건 읽기 전용             | 반영                                             |
| 다음 문서/다음 작업            | backend guidance         | 안내 + 단일 `진행하기`         | 반영                                             |
| 여러 next actions              | backend `next_actions[]` | 우선 액션 1개 + 전체 목록      | 우선 액션만 반영                                 |
| 데이터 기준, 생성일            | 표시                     | 메타 정보                      | 데이터 기준만 반영                               |

**입력박스로 만들지 않을 값:** 거래 단계, 거래금액, 통화, 인코텀즈, 결제방식, ETA, AR/AP, 선적 건수. 이 값들은 원문 필드 또는 연결된 업무 화면에서 수정되어야 한다.

### 리스크 허용 폼

- 사유: 거래처와 사전 합의, 허용 오차 범위, 내부 일정 조정, 기타.
- 기타 선택 시 상세 내용 필수.
- 성공 후 리스크 목록과 허용 이력을 다시 조회.
- Member는 허용 버튼 없이 리스크만 확인.

### 원가 입력 폼

- 유형 Select: 운임, 관세, 보험, 은행수수료, 내륙운송, 하역, 검사, 체선료, 기타.
- 금액 Number/Money input.
- 통화 Select 또는 통화 코드 input. 거래 기본 통화로 시작.
- 기준 Select: 가산, 가격 포함.
- 메모 Input.
- `추가`나 `수정`을 눌렀을 때만 폼을 연다. 기본 화면은 원가 목록과 합계만 표시한다.

### 관계자 입력 노출 방식

- `당사자 편집`: 행의 편집 버튼을 누르면 이름 입력 다이얼로그.
- `영업 담당자 연결`: 역할 + 담당자 검색을 작은 팝오버나 인라인 폼으로 노출.
- `멤버 공유`: 현재 사용자와 이미 공유된 멤버를 제외한 Select.
- `노트`: 반복 작업이므로 현재처럼 입력창 상시 노출.

## 남은 기능 우선순위

### P0. 요청 안정성

1. 전체 상세 loading과 느린 이전 요청 event guard.
2. 실제 API 401/403/404 및 타 조직 문서 연결 오류.

### P1. 상태 완결

1. 보관·복원.
2. 원가·노트·공유 하위 패널별 loading/error/empty.
3. API 재조회 실패 시 기존 데이터 유지와 배너 피드백.

### P2. 사용성 검증

1. 검색·탭·선택 상태 URL 복원.
2. 좁은 화면 단일 열 전환과 표 가로 스크롤 QA.

## 최종 UI 규칙

- **표시 유지:** 거래 360, 상업조건, 운영 현황, 필요 서류, 서류 대조, 건강도, 경제성, 신용 현황, 주문 진행, 선적, 이력.
- **상시 입력:** 거래 내 검색, 담당자 Select(권한자), 노트 Textarea.
- **버튼 후 입력:** 리스크 허용, 이슈 플래그, 주문 마감·수정·취소, 원가 추가·수정, 당사자 편집, 담당자 연결, 멤버 공유, SNAP 연결.
- **확인만:** 거래 삭제, 문서 연결 해제, 원가 삭제, 담당자/공유 해제, 주문 재오픈.
- **입력 금지:** 서버 파생 단계·금액·통화·인코텀즈·결제조건·ETA·AR/AP·GP를 상세 화면에서 직접 수정하지 않는다.
