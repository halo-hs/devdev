### 2.2 PR #262에 이미 포함되어 중복 작성하지 않을 내용

- 생성 문서는 Organization 공용 업무 자산이다.
- Owner, Admin, Member는 Organization 생성 문서를 조회할 수 있다.
- 작성 중 문서는 공동 편집 및 확정할 수 있다.
- 확정·발송된 문서는 변경할 수 없으며, 수정하려면 복제한다.
- Owner는 Organization의 모든 생성 문서를 삭제할 수 있다.
- Admin과 Member는 자신이 생성한 문서만 삭제할 수 있다.
- 생성자를 알 수 없는 문서는 Owner만 삭제할 수 있다.
- 삭제는 물리 삭제가 아닌 업무 보관 처리다.
- 삭제된 문서는 현재 목록과 고객 전달 대상에서 제외하고 활성 링크를 철회한다.
- 발행·전달 이력과 연결 관계는 보존한다.
- 생성자, 편집자, 확정자, 삭제자를 각각 기록한다.
- 생성 문서 접근 권한이 연결 거래나 유입 원문 접근 권한을 자동으로 부여하지 않는다.

### 2.3 PR #262 이후 부분 대체가 필요한 결정

PR #262에는 Pilot 단계에서 승인 UI를 숨기거나 기본 비활성화하는 내용이 있다. 최종 UI 및 기능 결정은 문서 확정 전에 승인 방식을 설정하는 흐름을 사용하므로, 승인 관련 문구는 아래 정책으로 부분 대체한다.

- 기본 경로는 승인 요청이다.
- 사용자는 `승인 없이 진행`을 선택할 수 있다.
- 승인자는 한 명 이상 복수 선택할 수 있다.
- 요청자는 자신의 승인자로 지정될 수 없다.
- 현재 소스 기준 후보 권한은 Owner/Admin이지만, 화면에서는 권한명이 아닌 `승인자`로 표현한다.
- 선택된 승인자 중 한 명이 승인하면 승인 완료로 처리한다.
- 한 명이 승인하면 나머지 승인 요청은 자동 종료한다.
- 반려되면 문서 확정을 차단한다.
- 반려 사유를 확인하고 문서를 수정한 뒤 재요청할 수 있다.
- 승인 요청·승인·반려·재요청 이력을 보존한다.
- 다음 문서에도 같은 승인자를 사용할 수 있도록 기본 승인자를 기억할 수 있다.
- PDF 검토, 거래 연결, 필수 점검을 완료한 뒤 승인 요청할 수 있다.
- 승인 요청 방식을 선택한 경우 승인 완료 전에는 문서를 확정할 수 없다.
- `승인 없이 진행`을 선택하면 다른 확정 조건이 모두 충족된 시점에 문서를 확정할 수 있다.
- `승인 없이 진행`을 선택한 사람과 시각을 기록한다. 별도 사유 입력은 요구하지 않는다.
- 승인 요청 이후 문서 항목, PDF 결과, 연결 거래 또는 대조 근거가 변경되면 기존 요청과 승인 결과를 무효화하고 승인 상태를 `요청 전`으로 되돌린다.

### 2.4 반영 분류와 PR 처리 순서

이 문서의 항목은 다음 규칙으로 해석한다.

- `[신규]`: 기존 SSOT에 없는 화면·상태·행동 규칙으로 새로 반영한다.

## 3. 공통 상태 모델

하나의 통합 상태값으로 모든 진행 상태를 표현하지 않는다. 업무 상태와 산출물 상태를 다음 축으로 분리한다.

| 상태 축             | 값                                                 |
| ------------------- | -------------------------------------------------- |
| 생성 문서 업무 상태 | 작성 중 / 확정 / 발송됨                            |
| PDF 산출물 상태     | 미생성 / 초안 PDF / 최종 PDF                       |
| 거래 연결 상태      | 미연결 / 연결                                      |
| 승인 상태           | 요청 전 / 승인 대기 / 승인 완료 / 반려 / 승인 없음 |
| 공유 링크 상태      | 미생성 / 활성 / 만료 / 철회                        |
| 전달 상태           | 전달 전 / 전달 완료 / 전달 실패                    |

생성 문서 목록의 PDF 표시는 다음과 같이 구분한다.

- PDF 미생성: 아이콘 비활성 또는 미생성 상태 표시
- 초안 PDF 생성: 초안 PDF 아이콘 및 다운로드 가능 상태 표시
- 최종 PDF 생성: 최종 PDF 아이콘 및 문서 다운로드 가능 상태 표시

`작성 중`이라는 업무 상태만으로 PDF 존재 여부를 추정해서는 안 된다. 작성 중 문서도 PDF 미생성 또는 초안 PDF 생성 상태일 수 있다.

## 4. 이슈 1 — 문서 올리기

### 4.1 이슈 목적

문서 유입, OCR 항목 검토, 거래 후보 확인과 연결까지를 하나의 흐름으로 정리한다. 문서 올리기는 생성 문서의 확정·승인·공유를 담당하지 않는다.

### 4.2 진입 화면과 대기 목록

- 진입 화면과 상세 검토 화면을 분리한다.
- 진입 화면에는 파일 추가 영역과 검토·배정 대기 문서 목록을 함께 표시한다.
- 대기 문서가 없는 최초 상태에서만 큰 드래그 앤 드롭 영역을 표시한다.
- 대기 문서가 있으면 별도 대형 업로드 영역을 계속 노출하지 않고, 목록 자체를 드롭 대상 영역으로 사용한다.
- 목록 위에는 PDF를 목록에 끌어놓아 추가할 수 있다는 안내를 표시한다.
- 검토·배정 대기 문서 영역 전체를 클릭하면 목록을 열고 닫을 수 있다. 제목 일부만 클릭해야 열리는 구조를 사용하지 않는다.
- `파일 추가`는 선택 메뉴로 제공한다.
  - 이메일에서 찾기
  - 폴더 선택
  - 파일 선택
- 대기 목록 열은 다음과 같다.
  - 문서 유형
  - 파일명
  - 등록일자
  - 상태
  - 작업
- 상태·문서 유형·최근 업로드 순 필터와 페이지네이션을 제공한다.
- 각 행의 케밥 메뉴에 삭제를 제공한다.
- 삭제는 물리 삭제가 아닌 업무 보관 처리이며 처리 이력과 기존 연결 관계는 보존한다.

### 4.3 상세 검토 레이아웃

- 상세 화면에는 상단 비주얼 영역을 사용하지 않는다.
- 전체 화면은 하나의 외곽 카드 안에서 좌우로 분할한다.
- 가운데 리사이즈 핸들로 두 패널 폭을 조절할 수 있다.
- 최초 비율은 50:50으로 표시한다.
- 좌우 패널은 각각 독립적으로 스크롤한다.
- 왼쪽에는 OCR 추출 항목을, 오른쪽에는 원본 PDF를 표시한다.
- 공통 PDF 뷰어를 사용한다.
  - 흰색 배경
  - 가로 폭에 맞춘 미리보기
  - 파일명
  - 확대·축소
  - 전체 화면
  - 페이지 이동
- 다음과 같은 중복 AI 요약 UI는 제거한다.
  - AI 추출 요약
  - 재사용 가능
  - 재사용 정보 수
  - PDF 근거 수
  - 신뢰도 높음 수
  - 검토 필요 수
- 넓은 화면에서는 단일 값 필드를 한 행에 두 개씩 표시할 수 있다.
- 품목은 테이블 또는 반복 그룹으로 표시한다.
- 오류, 누락, 확인 필요 상태를 색상만으로 구분하지 않고 상태 문구와 수행 액션을 함께 표시한다.

### 4.4 단위 입력 정책

- OCR이 읽은 단위를 최초 값으로 표시한다.
- 수량 단위는 사용자가 수정할 수 있다.
- 수량 단위는 고정된 제한 목록만 강제하지 않고 직접 입력을 허용한다.
- 단가는 `통화 / 수량 단위` 조합으로 표현한다.
- 단가 단위 전체 문자열을 임의 입력하게 하지 않고 통화 선택과 수량 단위의 조합으로 관리한다.
- 포장 수, 총중량, 순중량과 각 단위도 OCR 결과를 최초 값으로 사용하고 사용자가 수정할 수 있다.

### 4.5 거래 후보 확인 및 연결

- 필드 검토를 마친 뒤 거래 연결 단계로 이동한다.
- 문서에서 읽은 거래처, 금액, 통화, 식별번호 등을 기준으로 거래 후보를 찾는다.
- AI가 추천한 거래는 후보 행 오른쪽에 `AI 추천`으로 표시한다.
- 사용자가 거래를 선택한 뒤 명시적으로 연결한다.
- `선택한 거래 연결`은 목록 하단에 고립시키지 않고 패널 상단의 전역 액션으로 둔다.
- 거래가 연결되면 해당 거래 상세로 이동한다.
- 항목 검토로 돌아갈 수 있는 명시적 이전 액션을 상단에 제공한다.
- 검토와 연결 단계는 직접 URL로 접근할 수 있다.

거래 후보가 없을 때는 다음 두 경우를 구분한다.

1. 문서에서 거래처를 읽은 경우
   - 읽은 거래처를 표시한다.
   - 해당 거래처 아래 새 거래번호를 입력해 거래를 생성하고 연결한다.
2. 문서에서 거래처를 읽지 못한 경우
   - 새 거래처를 등록한다.
   - 거래번호를 입력해 거래를 생성하고 연결한다.

새로 생성된 거래는 샘플 화면의 임시 상태로 끝내지 않고 실제 거래 후보 및 거래 상세에서 다시 조회할 수 있어야 한다.

### 4.6 문서 올리기에서 제외할 기능

- 문서 확정
- 승인 요청 및 승인·반려 처리
- Magic Link 생성
- 이메일 전달
- 생성 문서 공유 관리

## 5. 이슈 2 — 문서 만들기

### 5.1 이슈 목적

문서 유형과 근거 정보를 선택해 내용을 작성하고, PDF 초안을 검토한 뒤 거래 연결·점검·승인을 거쳐 최종 문서를 확정하고 전달하는 전체 흐름을 정리한다.

### 5.2 목록과 진입

- 목록 화면과 상세 작성 화면을 분리한다.
- 목록 필터는 전체, 작성 중, 확정, 발송됨을 제공한다.
- 생성자를 표시한다.
- 거래 상세의 `이 거래로 문서 만들기`를 누르면 버튼 아래에서 문서 유형 선택 레이어를 표시한다.
- 문서 유형이 없는 빈 상세 화면으로 진입시키지 않는다.
- 작성 중 이탈하면 PDF가 아직 생성되지 않았더라도 작성 중 문서를 보존한다.
- 목록에서 다음 PDF 산출물 상태를 구분한다.
  - PDF 미생성
  - 초안 PDF 생성
  - 최종 PDF 생성
- 각 행의 케밥 메뉴에 삭제를 제공한다.
- 삭제 권한과 보관 정책은 PR #262의 Organization 생성 문서 정책을 따른다.

### 5.3 내용 입력

- 전체 화면은 하나의 외곽 카드 안에서 좌우로 분할한다.
- 가운데 리사이즈 핸들로 패널 폭을 조절할 수 있다.
- 최초 비율은 50:50이다.
- 왼쪽 패널에는 다음 정보를 둔다.
  - 문서 유형
  - 자연어 입력
  - 문서함에서 찾기
  - 거래에서 찾기
  - 선택한 근거 정보
- 오른쪽 패널에는 다음 정보를 둔다.
  - 문서 항목
  - 품목
  - 누락·오류·확인 필요 상태
- 자연어만 입력해서 문서를 만들 수 있다.
- 선택한 문서나 거래의 값은 선택 즉시 입력 필드에 반영하지 않는다.
- 사용자가 `항목에 반영`을 눌러야 선택한 근거가 필드에 적용된다.
- 문서함과 거래 검색 결과는 버튼을 눌러 별도 단계로 이동시키지 않고 입력 영역 아래에 고정해 표시한다.
- 문서 목록에는 매입·매출 방향을 표시한다.
- 문서 유형이 선택되지 않은 빈 상세 화면을 사용하지 않는다.

### 5.4 저장과 동시 편집

- 입력값은 디바운스 자동 저장한다.
- 상태를 다음과 같이 구분해 표시한다.
  - 자동 저장 대기
  - 저장 중
  - 저장됨
  - 저장 실패
- 자동 저장 대기 중에는 사용자가 즉시 저장할 수 있는 작은 `저장` 액션을 노출한다.
- 저장 실패 시 재시도 액션을 제공한다.
- 필드 변경 이력에는 다음을 기록한다.
  - 수정자
  - 수정 시각
  - 변경 전 값
  - 변경 후 값
- 동시 편집 충돌을 방지하기 위해 revision 또는 ETag를 사용한다.
- 오래된 revision으로 저장하면 `409 Conflict`로 거절하고 최신 값을 다시 확인하게 한다.

### 5.5 PDF 초안과 검토

- 필수 항목이 갖춰지면 PDF 초안을 생성할 수 있다.
- PDF 검토 완료 전에는 다운로드 버튼을 숨긴다.
- 검토 완료 후에는 초안 PDF를 다운로드할 수 있다.
- 거래가 연결되지 않은 상태에서도 검토가 끝난 초안 PDF는 다운로드할 수 있다.
- 초안과 최종본은 파일명 또는 다운로드 산출물 이름으로 구분한다.
- 문서가 확정되면 버튼 문구를 `초안 PDF 다운로드`가 아닌 `문서 다운로드`로 변경한다.
- 문서 확정 후에는 내용을 더 이상 수정할 수 없다.
- PDF 뷰어의 검토 완료 액션과 오른쪽 검토 영역의 안내가 중복된 별도 행동처럼 보이지 않도록 동일 상태에 연동한다.

### 5.6 문서 형태

- 기업 기본 로고가 등록된 경우에만 기본 로고 사용 옵션을 표시한다.
- 기본 로고가 없으면 새 로고 업로드가 기본 UI다.
- 로고는 드래그 앤 드롭 또는 파일 선택으로 업로드한다.
- 허용 확장자와 최대 용량을 표시한다.
- 문서 스타일은 모던과 클래식 중에서 선택한다.
- 강조색을 선택할 수 있다.
- 문서 스타일과 강조색은 한 행에 간결하게 배치한다.
- 문서 정보와 문서 형태는 각각 제목이 있는 그룹으로 구분하되 카드 안의 카드가 반복되지 않도록 한다.
- 문서 정보는 항목 옆에 값이 표시되는 읽기 쉬운 구조로 제공하며, 문서 유형에 따라 항목 수가 늘어날 수 있어야 한다.
- 품질 점수는 `문서 완성도`로 표현한다.

### 5.7 거래 연결과 문서 확정

- 거래 연결은 문서 작성을 시작하기 위한 필수 조건이 아니다.
- 미연결 문서는 작성, PDF 초안 생성, 검토, 초안 다운로드까지만 가능하다.
- 미연결 상태를 상단과 문서 진행 상태에 명확히 표시한다.
- 문서 확정을 위해서는 거래가 연결되어야 한다.
- 거래 미연결 상태에서는 공유 링크, 이메일 전달, Magic Link를 사용할 수 없다.
- 연결된 거래를 잘못 선택한 경우 거래 변경 또는 연결 해제를 제공한다.

문서 확정 조건:

1. 필수 항목 입력 완료
2. 변경사항 저장 완료
3. PDF 결과 검토 완료
4. 거래 연결 완료
5. 은행 거절 전 점검 통과 또는 비대상
6. 승인 완료 또는 승인 없이 진행 선택

- 모든 조건이 충족되면 상단에 `문서 확정` 주요 액션을 표시한다.
- 초안을 만든 뒤 항목 수정으로 돌아온 경우 다음 액션을 다시 `초안 만들기`로 고정하지 않는다.
- 문서 확정 전에 확정 후에는 수정할 수 없다는 안내를 표시한다.

### 5.8 은행 거절 전 점검

- 은행 제출과 관련된 문서에서만 실행한다.
- 거래가 연결되어 있고 대조할 거래 문서가 있을 때 실행한다.
- 거래처, 통화, 금액, 품목 등 발송 전 필수 대조 항목을 비교한다.
- 대조 기준이나 비교 문서가 없으면 `비대상`으로 처리하고 문서 확정을 차단하지 않는다.
- 점검 상태는 `미실행 / 통과 / 불일치 / 비대상`으로 저장한다.
- 통과 또는 비대상이어도 문서 진행 상태에서 결과를 확인할 수 있어야 한다.
- 불일치가 있는 경우에만 점검 영역을 펼쳐 표시한다.
- 불일치 표의 열은 다음과 같다.
  - 항목
  - 생성 문서 값
  - 대조 값
  - 근거 문서
  - 상태
- 제공 액션은 `항목 수정`과 `다시 점검`이다.
- 점검 영역 안에서 비교 문서를 직접 바꾸는 기능은 제공하지 않는다.
- 비교 기준을 바꾸려면 거래 연결이나 해당 거래의 연결 문서를 변경한다.
- `불일치를 확인했으며 이 상태로 확정` 같은 무시 체크박스는 제공하지 않는다.
- 미해결 거절 위험은 문서 확정을 차단한다.
- 문서 값, 연결 거래 또는 대조 문서가 변경되면 이전 점검 결과를 무효화하고 `미실행`으로 되돌린다.
- 비대상 판정 기준과 판정 주체는 감사 이력에 기록한다.
- 전체 5-Way 대조표는 거래 상세의 검증 영역에 유지하고, 문서 만들기에는 현재 문서 확정을 막는 불일치만 표시한다.

### 5.9 승인

- 승인 영역은 문서 정보, 문서 형태, 은행 거절 전 점검 다음에 배치한다.
- 카드 상단 오른쪽에 `승인 없이 진행` 체크박스를 제공한다.
- 승인자 복수 선택과 승인 요청 액션은 같은 행에 간결하게 배치한다.
- `다음 문서에도 이 승인자 사용`은 선택 레이어 안에서 설정할 수 있다.
- 승인 요청자 화면에는 승인 대기 상태와 요청 정보를 표시한다.
- 승인자 화면에는 승인·반려 액션을 표시한다.
- 반려를 선택하면 반려 사유 입력란으로 포커스를 이동한다.
- 반려 사유는 필수다.
- 승인 요청, 승인, 반려, 수정, 재요청 이력을 표시한다.
- 승인 대기 또는 반려 상태에서는 문서 확정을 표시하지 않거나 비활성화한다.
- 승인 요청은 PDF 검토, 거래 연결, 필수 점검 완료 후에만 가능하다.

### 5.10 완료와 공유

- 문서 확정 후 전달·공유 화면으로 이동한다.
- 한 문서에는 활성 Magic Link를 한 개만 운영한다.
- 링크 생성과 실제 전달 완료는 서로 다른 상태다.
- 완료 화면의 문서 진행 상태는 전체 단계를 펼친 형태로 표시한다.
- 공유 링크 상태는 미생성, 활성, 만료, 철회로 구분한다.
- 전달 상태는 전달 전, 전달 완료, 전달 실패로 구분한다.
- 받는 사람, 제목, 본문, 첨부 문서 선택은 공유 팝업에서 처리한다.
- 완료 화면에는 공유 링크 상태, 전달 이력, 공유 관리를 표시한다.
- 문서 만들기 완료 화면과 거래 상세의 `문서 고객 전달`은 같은 전달 흐름을 사용한다.
- 확정된 생성 문서 한 개를 주 문서로 사용한다.
- 거래에 연결된 유입 문서, 다른 확정 생성 문서, 기타 첨부 문서를 여러 개 동봉할 수 있다.

## 6. 이슈 3 — 거래

### 6.1 이슈 목적

거래 목록과 상세에서 거래번호를 중심으로 정보를 정리하고, 주문·선적·정산·관계자·서류·고객 전달을 한 거래 맥락에서 처리하도록 구성한다.

### 6.2 거래 목록

- 거래번호를 가장 중요한 식별자로 표시한다.
- 한글 거래 설명은 거래번호 아래 부가 정보로 표시한다.
- 거래처명과 대표 품목을 표시한다.
- 품목이 여러 개인 경우 `대표 품목 외 N건`으로 표시한다.
- 거래번호와 한글 설명은 함께 수정할 수 있다.
- 페이지네이션을 제공한다.
- 각 거래 행에 케밥 메뉴를 제공한다.
- 케밥 메뉴에 삭제를 제공한다.
- 거래 삭제는 업무 보관 처리다.
- 삭제된 거래는 현재 거래 목록과 집계에서 제외한다.
- 연결 문서와 변경 이력은 보존한다.
- 삭제 권한은 기존 Deal 권한 범위를 따른다.
  - Owner/Admin: Organization 범위 거래
  - Member: 자신에게 배정되거나 공유된 거래
- Owner만 삭제된 거래 목록을 보고 복구할 수 있다.
- 일반 UI에서는 영구 삭제를 제공하지 않는다.

### 6.3 거래 상세 공통 구조

- 상단 비주얼 영역을 사용하지 않는다.
- 전체 폭 상세 화면을 사용한다.
- 상세 편집과 거래 서류 영역을 하나의 외곽 카드 안에서 좌우로 분할한다.
- 가운데 리사이즈 핸들로 패널 폭을 조절할 수 있다.
- 최초 비율은 50:50이다.
- 좌우 패널은 각각 독립적으로 스크롤한다.
- 직접 접근 경로는 `/erp/deals/{dealId}` 형식으로 제공한다.

최상단 주요 액션:

- 이 거래로 문서 올리기
- 노트 추가
- 이 거래로 문서 만들기
- 문서 고객 전달

그 외 배치 원칙:

- 담당자와 공유 대상은 세계시간과 가까운 헤더 영역에 표시한다.
- Owner 화면 등 역할 미리보기 정보는 케밥 메뉴 안으로 이동한다.
- 거래번호와 한글 설명을 수정할 수 있다.
- 거래 삭제는 케밥 메뉴에서 수행한다.

### 6.4 탭 구조

- 요약
- 상세
- 주문·선적
- 정산
- 관계자

기존 한 페이지의 내용을 억지로 잘게 분리하지 않는다. 바로 확인해야 하는 정보는 요약에 유지하고, 업무 성격이 다른 묶음만 탭으로 분리한다.

### 6.5 요약

- 거래 요약을 상단에 표시한다.
- 확인할 문제나 다음 작업이 있으면 요약 아래에 안내한다.
- 안내가 여러 개인 경우 총 개수와 이전·다음 이동을 제공한다.
- 왼쪽에는 업무 진행과 거래 조건을 배치한다.
- 오른쪽에는 변경·불일치 검증과 거래 건강도를 배치한다.
- 변경·불일치 검증은 실제 이슈가 있을 때만 표시한다.
- 거래 건강도는 과도한 내부 카드 없이 텍스트와 가로 그래프로 표시한다.
- 정산 관련 건강도 항목에는 정산 바로가기를 제공한다.
- `사유와 함께 허용`은 별도 팝업을 띄우지 않고 해당 이슈 안에서 처리한다.

### 6.6 주문·선적·정산

- 주문 정보와 주문 수정 이력은 하나의 묶음으로 구성한다.
- 주문 수정 이력은 기본 접힘 상태로 두고 필요할 때 펼친다.
- 선적은 선적 건별 카드로 구분한다.
- 선적 한 건이 끝나면 해당 선적 건의 정산을 진행할 수 있다.
- 모든 선적이 끝난 뒤 전체 정산을 진행할 수 있다.
- 건별 정산과 전체 정산을 모두 지원한다.
- 원가 추가는 팝업이 아닌 페이지 안의 인라인 입력으로 처리한다.

### 6.7 관계자, 공유 대상, 노트, 활동 이력

- 당사자는 2열로 배치한다.
- 연락처도 2열로 배치한다.
- 공유 대상은 거래를 함께 보는 내부 직원이며 본문 편집 영역이 아닌 상단 헤더에서 관리한다.
- 노트와 활동 이력을 구분한다.
- 노트는 업무자 간 공유 메모다.
- 노트는 추가, 수정, 삭제할 수 있다.
- 활동 이력은 거래에서 발생한 전체 변경의 감사 기록이며 수정하지 않는다.

### 6.8 거래 서류

- 거래 서류 전체 개수를 표시한다.
- 중요 서류 슬롯은 다음 다섯 종류다.
  - 판매계약서(SC)
  - 발주서(PO)
  - 상업송장(CI)
  - 포장명세서(PL)
  - 선하증권(B/L)
- 중요 서류와 기타 서류를 같은 상단 선택 행에서 구분한다.
- 중요 서류를 선택하면 해당 PDF를 바로 연다.
- 기타 서류를 선택하면 기타 서류 목록을 연다.
- 기타 서류 전용 검색 UI는 제거한다.
- `서류 추가`는 다음 두 선택지만 제공한다.
  - 문서 올리기에서 추가
  - 파일 직접 추가
- 미비한 선하증권 슬롯을 선택하면 다음 액션만 제공한다.
  - 취소
  - 문서 올리기로 이동
- PDF 헤더에서 거래 연결 해제를 제공한다.
- 유입 문서와 생성 문서는 모두 거래 서류 및 고객 전달 동봉 문서가 될 수 있다.

### 6.9 문서 고객 전달

- 최상단 주요 버튼 문구는 `문서 고객 전달`로 사용한다.
- 확정된 생성 문서 한 개를 주 문서로 선택한다.
- 거래에 연결된 유입 문서, 다른 확정 생성 문서, 기타 첨부 문서를 여러 개 동봉할 수 있다.
- 버튼에 전달 가능한 생성 문서 개수를 표시한다.
- 확정되지 않은 생성 문서는 주 문서로 선택할 수 없다.
- 받는 사람, 제목, 본문, 첨부 문서, Magic Link 설정은 팝업에서 처리한다.
- 공유 링크 생성 상태와 고객 전달 완료 상태를 구분한다.

## 7. 공통 정보 구조와 라우팅

### 7.1 상세 URL

- `/erp/documents/upload`
- `/erp/documents/upload/{documentId}/review`
- `/erp/documents/upload/{documentId}/connect`
- `/erp/documents/create`
- `/erp/documents/create/{documentId}`
- `/erp/ai`
- `/erp/copilot` → `/erp/ai` 리다이렉트
- `/erp/deals`
- `/erp/deals/{dealId}`

상세 경로에는 변경되지 않는 내부 식별자를 사용한다. 파일명, 문서번호, 거래번호는 표시·검색 값이며 라우팅 식별자로 사용하지 않는다.

상세 페이지 URL은 복사해 다른 브라우저나 사용자에게 전달해도 같은 상세 상태로 접근할 수 있어야 한다. 2단계 화면은 1단계 메모리 상태에만 의존하지 않고 URL 식별자로 필요한 상태를 복원해야 한다. 단, 해당 자원 접근 권한이 있는 사용자만 복원할 수 있으며 권한이 없는 사용자는 데이터 노출 없이 `403 Forbidden`을 받는다.

### 7.2 화면 구성 원칙

- 상단 비주얼 영역은 문서 올리기와 문서 만들기 진입 화면에만 사용한다.
- `AI에게 묻기`는 상단 비주얼을 붙이지 않고 전체 높이의 대화형 작업 화면으로 제공한다.
- 상세 화면과 전체 폭 화면에는 비주얼 영역을 사용하지 않는다.
- 본문 배경은 회색, 카드는 흰색, 사이드바는 흰색으로 통일한다.
- 분할 상세 화면은 카드 두 개가 나란히 놓인 모양이 아닌 하나의 외곽 카드와 중앙 리사이즈 핸들로 표현한다.
- 문서 올리기, 문서 만들기, 거래 상세의 PDF 뷰어 조작부와 패널 구조를 공통화한다.
- 문서 만들기와 AI에게 묻기의 자연어 입력은 최소 네 줄 이상의 textarea를 사용한다.
- 알림은 팝업 중심이 아니라 GitHub Notifications와 같은 별도 페이지로 제공한다.
- 알림 버튼은 워크스페이스 전환 영역 가까이에 배치한다.
- 현재 사용자가 수행해야 하는 업무 알림은 목록 또는 상세 상단의 인라인 알림으로 표시한다.

`AI에게 묻기`와 전역 알림 페이지 변경은 문서 올리기·문서 만들기·거래의 세 기능 이슈에 섞지 않는다. `AI에게 묻기`는 FS-17 및 독립 화면 명세 변경으로, 전역 알림은 별도 공통 UI 이슈로 관리한다. 이번 세 기능의 SSOT에는 각 화면에서 필요한 인라인 업무 알림만 포함한다.

### 7.3 홈 대시보드와 빈 상태

- 홈의 데이터가 없거나 조회에 실패해도 페이지 전체를 단일 빈 화면으로 대체하지 않는다.
- 상단 AI 질문·바로가기 영역, 오늘 확인할 업무, 진행 현황·받을 돈, 업무 요약 지표, 선적 일정의 기본 골격을 유지한다.
- 정상적으로 값이 없는 경우는 `0건`, 조회하지 못했거나 계산할 수 없는 경우는 `—`로 구분한다.
- 최초 사용 상태의 주요 시작 액션은 `오늘 확인이 필요합니다` 영역에만 표시한다.
  - 문서 올리기
  - 문서 만들기
- 조회 오류는 영향을 받은 영역 안에서 설명하고 `다시 불러오기`를 제공한다. 다른 정상 영역의 값은 지우지 않는다.
- 본문은 회색 캔버스와 흰색 카드로 구성하고, 기본 데스크톱 배치는 다음 순서를 사용한다.
  1. 상단 AI 질문·업무 바로가기 영역
  2. 왼쪽 주요 업무와 오른쪽 진행 현황·받을 돈
  3. 전체 폭 업무 요약 지표
  4. 전체 폭 선적 일정
- 상태별 화면 검증을 위해 기본, 빈 상태, 최초 사용, 조회 오류 시안을 각각 제공한다.
- 전역 Tailwind `--spacing` 기준은 변경하지 않는다. 페이지 여백, 대시보드 간격, 패널 안쪽 여백처럼 반복되는 값은 `@ecoya/ui`의 의미 기반 레이아웃 토큰으로 정의하고 `@theme`에서 이름을 연결한다.

### 7.4 AI에게 묻기 대화형 레이아웃

#### 화면·라우팅

- `AI에게 묻기`는 홈 안의 고정 질문 카드가 아니라 독립 대화 화면 `/erp/ai`로 제공한다.
- 기존 `/erp/copilot`은 독립 화면을 만들지 않고 `/erp/ai`로 이동시키는 호환 경로로 변경한다.
- 데스크톱은 대화 본문을 주 영역으로 사용하고 대화 기록을 오른쪽 보조 패널에 배치한다.
- 모바일·좁은 화면에서는 같은 대화 기록을 오른쪽 Sheet로 연다.
- 대화 기록 패널은 열고 닫을 수 있으며, 닫았을 때 대화 본문이 남은 폭을 사용한다.
- 대화 작업공간 외곽은 별도 카드 폭으로 제한하지 않고 사용 가능한 본문 높이와 폭을 채운다. 답변 본문에는 가독성을 위한 최대 읽기 폭을 둘 수 있다.

#### 새 대화와 질문 입력

- 새 대화 상태에는 `ECOYA 업무 AI`, 사용 목적, 질문 입력창, 대표 질문 바로가기를 표시한다.
- 질문 입력은 최소 네 줄 높이의 textarea를 사용한다.
- 전송은 버튼과 `⌘/Ctrl + Enter`를 지원한다.
- 빈 질문은 제출할 수 없다.
- 대표 질문은 거래, 문서, 정산, 승인처럼 사용자가 즉시 확인할 수 있는 실제 업무 범위를 사용한다.
- 기능이 연결되지 않은 장식용 버튼은 노출하지 않는다.

#### 답변과 근거

- 한 대화 안에서 사용자 질문과 AI 답변을 시간 순서대로 함께 표시한다.
- AI 답변에는 답변 기준 시각을 표시한다.
- 답변의 업무 근거는 별도의 고정 카드나 독립 우측 파일 패널로 떼지 않고 해당 답변 아래에 포함한다.
- 답변을 스크롤하면 그 답변의 근거도 함께 이동한다.
- 근거 행에는 제목, 요약 정보, 유형을 표시하고 선택하면 접근 권한이 있는 거래·문서·정산·성과 화면으로 이동한다.
- 근거가 없는 경우 만들어낸 답을 표시하지 않고 `확인할 수 없음` 또는 `참조할 업무 데이터 없음`으로 구분한다.
- 답변별로 복사, 다시 생성, 도움이 됨, 도움이 되지 않음 액션을 제공하며 실제 동작이 연결된 경우에만 노출한다.

#### 대화 기록

- 오른쪽 대화 기록에는 새 대화, 검색, 날짜별 그룹, 선택한 대화 상태를 제공한다.
- 기록을 선택하면 해당 질문과 상태를 대화 본문에서 다시 연다.
- 검색 결과가 없으면 기록 패널 안에 빈 결과를 표시한다.
- 대화 기록과 답변 근거는 서로 다른 정보다. 대화 기록은 대화 단위 탐색이고, 답변 근거는 특정 답을 만든 업무 데이터다.

#### 상태와 복구

| 상태             | 화면 표시                                  | 사용자가 할 수 있는 일            |
| ---------------- | ------------------------------------------ | --------------------------------- |
| 새 대화          | 질문 입력과 대표 질문                      | 질문 작성·제출                    |
| 답변 생성 중     | 진행 문구와 스켈레톤                       | 현재 질문 유지                    |
| 최신 데이터 대기 | 문서 분석 등 선행 작업 대기 안내           | 다시 확인                         |
| 검색 결과 없음   | 일치하는 업무를 찾지 못했다는 안내         | 식별자·조건을 바꿔 다시 질문      |
| 참조 자료 없음   | 연결된 거래·문서·정산 근거가 없다는 안내   | 관련 문서 올리기 또는 데이터 연결 |
| 답변 완료        | 답변, 기준 시각, 근거 행                   | 근거 열기·복사·재생성·피드백      |
| API·모델 실패    | 실패 원인을 근거 없음과 구분하고 입력 보존 | 같은 질문 재시도 또는 범위 수정   |

현재 시안에는 새 대화, 답변 완료, 검색 결과 없음, 참조 자료 없음, 답변 생성 중, 최신 데이터 대기 상태가 구현되어 있다. API·모델 실패는 기존 `FS-17` 계약을 유지하는 후속 구현 확인 항목이다.

#### 정본 연결과 구현 참조

- 제품 기능 정본은 `FS-17` 자연어 질문 계약을 확장한다.
- 홈에서 질문을 시작하는 동작은 `SC-09`에 남기되, 제출 후 독립 대화 화면으로 이동하는 경계를 명시한다.
- 신규 `/erp/ai` 화면은 `SC-45`로 추가하고 `functional-specs/screens/README.md`의 화면 수, 주소, 담당 흐름을 함께 갱신한다.
- `SC-12 /erp/copilot` 문서는 리다이렉트 대상을 기존 `/erp/home#ask`에서 `/erp/ai`로 변경한다.
- 질의 처리 자체는 기존 `POST /api/v1/trade/nlq`의 읽기 전용 SQL 생성, 조직·테이블·문법 검증, 결과 요약 계약을 유지한다.
- 대화 기록의 저장 단위, 보존 기간, 검색 API, 삭제 권한은 현재 FS-17에 정의되어 있지 않으므로 데이터·API 선결 항목으로 분리한다.
- UI 참고는 Open WebUI `v0.6.5`의 대화 레이아웃 패턴으로 한정하며 BSD-3-Clause 고지와 출처를 유지한다. ECOYA 화면은 제품 디자인 토큰과 업무 정보 구조를 사용한다.

### 7.5 정본 용어

| 개념                      | 정본 용어 | UI 표현 또는 보조 표기     |
| ------------------------- | --------- | -------------------------- |
| 시스템이 생성한 문서      | 생성 문서 | 메뉴명은 `문서 만들기`     |
| 삭제 처리                 | 업무 보관 | UI 액션은 `삭제`           |

## 9. 화면 캡처 목록

### 9.1 문서 만들기

`18-generated-document-create.md`에는 최소 다음 다섯 상태의 캡처와 상세 설명을 추가한다.

4. 승인 진행
   - 요청자 승인 대기 화면
   - 승인자 승인·반려 화면
   - 반려 사유와 재요청 상태
5. 문서 확정·전달
   - 최종 PDF 다운로드
   - Magic Link 상태
   - 전달 이력
   - 공유 관리

각 캡처에는 다음을 함께 기술한다.

- 진입 조건
- 현재 상태
- 사용 가능한 주요 액션
- 비활성 액션과 비활성 사유
- 다음 상태로 이동하는 조건
- 권한별 차이

### 9.2 AI에게 묻기

신규 `/erp/ai` 화면 명세에는 최소 다음 상태의 캡처와 설명을 추가한다.

1. 새 대화
   - 전체 폭 대화 본문
   - 네 줄 이상 질문 입력
   - 대표 질문 바로가기
   - 오른쪽 대화 기록
2. 답변 완료
   - 사용자 질문과 AI 답변
   - 답변 기준 시각
   - 답변 아래의 거래·문서·정산 근거
   - 복사·다시 생성·피드백
3. 검색 결과 없음
   - 일치하는 업무 없음 안내
   - 질문 조건 수정 유도
4. 참조 자료 없음
   - 근거 없는 답변 차단
   - 문서 올리기 등 복구 동작
5. 답변 생성 중·최신 데이터 대기
   - 진행 상태
   - 입력과 대화 유지
   - 다시 확인
6. 좁은 화면
   - 오른쪽 Sheet 형태의 대화 기록
   - 패널을 닫았을 때 대화 본문 유지

API·모델 오류 캡처는 `400`, `403`, `429`, 모델 미설정, 시간 초과, 서비스 실패가 근거 없음 상태와 구분되는지 함께 검증한다.

## 10. 제외·제거할 항목

- 문서 올리기에서 문서 확정, 승인, Magic Link, 이메일 공유를 제공하지 않는다.
- 거래에서 문서 만들기를 시작할 때 문서 유형이 없는 빈 상세 화면으로 이동하지 않는다.
- 문서나 거래를 선택하는 즉시 생성 문서 필드에 자동 반영하지 않는다.
- 한 문서에 활성 Magic Link 여러 개를 만들지 않는다.
- 은행 거절 전 점검 안에서 비교 문서를 직접 변경하지 않는다.
- 은행 거절 위험을 무시하고 확정하는 체크박스를 제공하지 않는다.
- AI 추출 요약, 재사용 가능, 근거 수, 신뢰도 수 등 중복 설명과 뱃지를 반복 노출하지 않는다.
- 생성 문서 업무 상태와 PDF 산출물 상태를 하나의 상태로 합치지 않는다.
- 일반 UI에서 문서나 거래의 영구 삭제를 제공하지 않는다.
- AI 답변의 근거를 대화와 분리된 고정 패널로 표시하지 않는다.
- 데스크톱 대화 기록을 왼쪽 고정 사이드바로 배치하지 않는다.
- 동작하지 않는 공유·첨부·재생성·피드백 버튼을 장식용으로 노출하지 않는다.

## 11. 데이터·API 후속 확인 항목

### 11.1 SSOT 반영 전에 확정할 정책

- 유입 문서의 보관 목록 조회와 복구 권한
- 생성 문서의 보관 목록 조회와 복구 권한
- `승인 없이 진행`을 선택할 수 있는 역할 범위
- 은행 거절 전 점검의 문서 유형별 대상 판정 기준
- 은행 거절 전 점검의 비대상 판정 주체

위 항목은 구현 방식이 아니라 제품 정책이므로, 미확정 상태로 API 작업에 넘기지 않는다.

### 11.2 데이터·API 구현 확인

- 생성 문서의 PDF 산출물 상태: 미생성 / 초안 / 최종
- 생성자 식별값: `created_by_account_id`
- 승인 요청, 승인, 반려, 재요청 이벤트와 시각
- 반려 사유
- 기본 승인자 저장 범위
- 동시 편집 revision 또는 ETag
- 한 문서당 활성 Magic Link 한 개 제약
- 거래 업무 보관·복구 상태와 처리자·처리 시각
- 문서 유입 방식: 이메일 / 폴더 / 파일 / 드래그 앤 드롭
- 거래 후보 추천 근거와 추천 점수
- 문서에서 추출한 거래처가 기존 거래처인지 신규 거래처 후보인지 구분하는 값
- 초안 PDF와 최종 PDF의 파일명 및 다운로드 정책
- `/erp/ai` 대화 ID와 URL 복원 정책
- 대화 기록의 저장 단위, 보존 기간, 검색·삭제 권한
- 다중 턴 문맥에 포함하는 이전 질문·답변·근거 범위
- 답변 기준 시각과 근거 원천별 최신성 표시값
- 질문 취소, 스트리밍 중단, 재생성 API 지원 여부

### 11.3 기능 이슈 작성 형식

세 기능 이슈는 각각 다음 항목을 포함한다.

1. 기존 정본 참조
2. 신규·대체 결정
3. 상태 전이
4. 역할별 권한
5. 예외·오류
6. 데이터·API 요구
7. 수정할 SSOT 위치
8. 인수 조건
