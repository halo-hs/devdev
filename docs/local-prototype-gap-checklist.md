# 원소스 대비 로컬 프로토타입 기능 갭 체크리스트

기준일: 2026-07-10
원소스 기준: `docs/source-functional-checklist.md`
비교 대상: `src/App.tsx` 및 `http://127.0.0.1:5175/`

## 판정

- `구성됨`: 화면과 로컬 상태 전환이 의도대로 동작한다.
- `부분`: UI는 있으나 정적 데이터이거나 다음 기능과 연결되지 않는다.
- `누락`: 원소스 필수 기능을 표현하는 화면/상태가 없다.
- 이 프로토타입에는 업무 API 호출이 없다. `구성됨`도 운영 기능 완료가 아니라 UX 프로토타입 완료를 뜻한다.

## 핵심 결론

현재 로컬은 화면 구조와 주요 상태 표현은 많이 들어왔지만, 원소스 기능 이식은 아직 아니다. `App.tsx`의 정적 배열과 `useState`로만 동작하며 파일 업로드, OCR, 저장, 거래 연결, 문서 생성, 승인, PDF, 전달 API가 연결되어 있지 않다.

브라우저에서 확인한 즉시 수정 대상은 프로토타입에 반영했다.

- [x] 실제 file picker/drag-and-drop과 PDF·개수·용량 검증
- [x] 선택 템플릿별 제목·필드·PDF 반영
- [x] 출처 파일을 모두 해제한 빈 입력 상태의 생성 차단
- [x] 업로드 문서 유형별 Trigger와 누락 필드 표시
- [x] 거래 후보 없음·지정 거래·stale 거래 상태 분기

## 8. 필수 운영 엣지케이스

아래 항목은 현재 로컬에 모두 없다.

- [ ] bootstrap/API 실패 후 재시도
- [ ] 느린 응답이 현재 화면을 덮지 않는 event/ref guard
- [ ] 저장·확정·링크·첨부·다운로드 중복 클릭 방어
- [ ] 이미 commit된 문서 stale tab 처리
- [ ] 신규 거래 생성 후 assign 실패 재시도
- [ ] draft/void 문서 고객 전달 차단
- [ ] quality blocking/missing required/approval required 오류 구분
- [ ] 링크 expired/maxed/revoked 상태별 재생성 안내
- [ ] mailto recipient sanitization
- [ ] OCR blob missing/failed job 처리
- [ ] 첨부 deal mismatch
- [ ] 이메일 unknown sender/중복 message/다중 첨부 idempotency

## 구현 우선순위

### P0 - 지금 화면의 의미가 달라지는 항목
